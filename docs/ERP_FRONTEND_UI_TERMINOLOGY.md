# ERP 前端 UI 术语表

> 2026-09-09：新 UI 已改为 Rust 原生桌面与 WASM Web，共享 egui。下文业务术语可参考；React、DOM、路由/测试入口等技术规则仅适用于冻结旧前端，不约束新 UI。当前规则见 [UI 指南](FRONTEND_GUIDE.md) 与 [组件库规范](UI_COMPONENT_LIBRARY.md)。


> 适用范围：`apps/erp-web` 内所有用户可见 UI 文案，包括按钮、菜单、标题、表格列名、筛选项、空态、错误提示、确认弹窗、`aria-label`、操作日志展示文案和 E2E 可感知文案。  
> 核心目标：让 ERP 用户在订单、商品、仓储、采购、售后、财务、系统设置等模块中复用同一套操作语言，降低学习成本和误操作概率。  
> 编码要求：本文档和后续新增 UI 文案统一使用 UTF-8；用户可见文案不得显示 `\uXXXX` 转义串或乱码。

## 1. 总体原则

### 1.1 一词一义

同一个动作、状态、对象在全系统中优先使用同一个词。业务特殊术语可以保留，但必须在术语表中登记，避免同一页面或跨页面混用。

### 1.2 用户视角优先

术语应描述用户要完成的业务动作，而不是开发实现细节。例如使用“刷新”而不是“重新拉取接口”，使用“列设置”而不是“字段配置弹层”。

### 1.3 高频动作短句化

ERP 高频按钮应短、稳、明确。按钮文案优先使用 2 到 4 个汉字；确认提示和错误提示再补充原因、影响和下一步建议。

### 1.4 危险动作显式化

删除、作废、取消、关闭、覆盖、清空、重置等动作必须明确影响范围。危险动作不得只写“确定”，确认按钮应重复危险动作本身，例如“确认删除”“确认作废”。

### 1.5 无障碍文案中文化

`aria-label`、`title`、空态说明、错误提示和屏幕阅读器专用文案应使用中文，并包含对象与动作，避免仅用图标名称或英文缩写。

## 2. 统一动作词

| 场景 | 推荐用词 | 说明 | 禁止混用词 |
|---|---|---|---|
| 执行条件检索 | 查询 | 用于按筛选条件拉取列表数据 | 搜索、检索、查找 |
| 输入框即时匹配 | 搜索 | 用于功能搜索、菜单搜索、输入框局部搜索 | 查询、检索 |
| 清除筛选条件 | 重置 | 回到默认筛选条件，不代表删除业务数据 | 清空、恢复、初始化 |
| 重新获取当前数据 | 刷新 | 保留当前筛选、分页、视图配置 | 重新加载、更新、重载 |
| 新增业务对象 | 新增 | 列表页主按钮，创建一条新记录 | 新建、添加、创建 |
| 修改已有对象 | 编辑 | 修改已存在记录 | 修改、维护 |
| 查看只读信息 | 查看 | 只读打开详情或预览 | 详情、浏览 |
| 保存草稿或配置 | 保存 | 持久化当前修改 | 提交、确认 |
| 发起审批或流转 | 提交 | 将单据送入下一流程 | 保存、送审 |
| 通过审批 | 审核通过 | 明确结果为通过 | 通过、同意 |
| 驳回审批 | 审核驳回 | 明确结果为驳回 | 驳回、拒绝 |
| 取消未完成动作 | 取消 | 关闭当前操作，不改变已保存数据 | 关闭、返回 |
| 退出当前层级 | 返回 | 回到上一页或上一层 | 后退、关闭 |
| 移除记录 | 删除 | 删除数据或解除绑定，必须确认 | 移除、清除 |
| 使单据失效 | 作废 | 业务上保留记录但不可继续流转 | 取消、废弃 |
| 停止启用状态 | 停用 | 对基础资料、账号、规则等禁用 | 禁用、关闭 |
| 恢复可用状态 | 启用 | 对基础资料、账号、规则等启用 | 开启、激活 |
| 批量处理选中记录 | 批量操作 | 作为更多操作分组名称 | 批处理、批量处理 |
| 导入外部数据 | 导入 | 从文件或外部来源写入系统 | 上传、导入文件 |
| 导出系统数据 | 导出 | 从系统生成文件 | 下载、输出 |
| 下载固定模板 | 下载模板 | 用于导入前获取模板文件 | 导出模板、获取模板 |
| 打开列配置 | 列设置 | 表格列显示、顺序、固定等统一入口 | 字段设置、列配置、表头设置 |
| 恢复默认视图 | 恢复默认 | 对列、密度、视图等配置恢复系统默认 | 重置视图、默认配置 |

## 3. 禁止混用词规范

### 3.1 查询与搜索

- 列表页按条件获取数据：统一使用“查询”。
- 顶部功能搜索、菜单搜索、命令面板、输入框即时过滤：统一使用“搜索”。
- 不要在同一列表页同时出现“查询按钮”和“搜索按钮”表示同一件事。

### 3.2 新增、新建、添加、创建

- 主按钮统一使用“新增”。
- 弹窗标题可使用“新增 XXX”。
- 禁止同一业务对象混用“新建商品”“添加商品”“创建商品”。
- 如果是把已有对象加入集合，例如“添加商品到组合套装”，可以使用“添加”，但应避免与“新增商品”混淆。

### 3.3 作废、取消、关闭

- 单据业务失效：使用“作废”。
- 放弃当前未保存操作：使用“取消”。
- 关闭弹窗、抽屉、面板：使用“关闭”。
- 不要用“取消订单”表达“作废订单”，除非业务定义确实叫取消订单，并已在术语例外中登记。

### 3.4 启用、停用、开启、关闭

- 业务资料、规则、账号、渠道状态：使用“启用”和“停用”。
- 面板、弹窗、开关控件的展开收起：使用“打开”和“关闭”或“展开”和“收起”。
- 不要将“关闭规则”和“停用规则”混用。

### 3.5 导入、上传、下载、导出

- 用户把数据写入系统：使用“导入”。
- 用户上传附件、图片、凭证：使用“上传”。
- 用户从系统导出业务数据：使用“导出”。
- 用户下载固定文件、模板、附件：使用“下载”。

### 3.6 保存、提交、确认

- 保存表单或设置：使用“保存”。
- 推进流程、送审、生成任务：使用“提交”。
- 确认弹窗中的最终按钮：根据动作写成“确认删除”“确认作废”“确认提交”，不要单独使用“确认”承载业务语义。

## 4. 表格术语

| 场景 | 推荐文案 | 使用说明 | 禁止混用 |
|---|---|---|---|
| 主数据区域 | 主表 | 页面主体自研 DataGrid 数据区域 | 列表区、表区 |
| 行序号列 | 序 | 表头固定为“序” | 序号、编号 |
| 勾选列 | 选择 | 表头或 aria 文案使用 | 勾选、复选 |
| 表格无数据 | 暂无数据 | 通用空态标题 | 无记录、没有数据 |
| 筛选后无结果 | 暂无符合条件的数据 | 查询结果为空 | 未查询到、无匹配 |
| 加载中 | 数据加载中 | 表格请求中 | 加载、读取中 |
| 加载失败 | 数据加载失败 | 搭配“重试”按钮 | 获取失败、请求失败 |
| 分页总数 | 共 {total} 条 | 分页汇总 | 合计、总记录 |
| 已选数量 | 已选 {count} 条 | 批量操作区 | 选中、已勾选 |
| 清除选择 | 清除选择 | 取消当前勾选 | 取消勾选、清空选择 |
| 全选当前页 | 全选当前页 | 仅当前页范围 | 全选、选择全部 |
| 反选当前页 | 反选当前页 | 当前页内反向选择 | 反选、反向选择 |
| 固定列 | 固定列 | 列设置项 | 冻结列、锁定列 |
| 取消固定 | 取消固定 | 列设置项 | 解锁、取消冻结 |
| 空值展示 | — | 表格空值统一展示，不写“无” | 无、空、N/A |

### 4.1 表格列名规范

- 列名应使用业务名词，不使用接口字段名。
- 金额列建议包含币种或单位，例如“实付金额”“退款金额”。
- 数量列建议明确对象，例如“商品数量”“锁定数量”。
- 时间列统一使用“创建时间”“更新时间”“审核时间”“发货时间”，不要混用“日期”“时间点”。
- 状态列统一使用“状态”，需要区分时写成“订单状态”“发货状态”“审核状态”。

### 4.2 表格操作列规范

- 操作列表头统一使用“操作”。
- 高频单行操作优先展示 1 到 3 个；低频操作进入“更多”。
- 危险操作在更多菜单中仍需使用危险色和确认弹窗。
- 行内按钮文案应与工具栏动作词保持一致。

## 5. 列设置术语

| 场景 | 推荐文案 | 说明 | 禁止混用 |
|---|---|---|---|
| 入口 | 列设置 | 统一按钮和 aria-label | 字段设置、列配置 |
| 弹窗标题 | 列设置 | 不按页面改名 | 表格设置、显示设置 |
| 显示列 | 显示 | 控制列是否展示 | 可见、展示 |
| 隐藏列 | 隐藏 | 控制列不展示 | 不显示、关闭 |
| 固定到左侧 | 固定到左侧 | 列固定方向 | 左冻结、锁定左侧 |
| 固定到右侧 | 固定到右侧 | 列固定方向 | 右冻结、锁定右侧 |
| 取消固定 | 取消固定 | 解除列固定 | 解除冻结 |
| 上移 | 上移 | 调整列顺序 | 向上、前移 |
| 下移 | 下移 | 调整列顺序 | 向下、后移 |
| 恢复默认 | 恢复默认 | 恢复系统列配置 | 重置列、默认列 |
| 保存视图 | 保存视图 | 持久化当前列和筛选配置 | 保存配置 |
| 应用视图 | 应用视图 | 切换到已保存视图 | 使用视图 |

### 5.1 列设置 aria-label

列设置相关图标按钮必须使用明确中文 `aria-label`：

- `aria-label="列设置"`
- `aria-label="隐藏列：商品名称"`
- `aria-label="固定到左侧：订单编号"`
- `aria-label="上移列：实付金额"`
- `aria-label="恢复默认列设置"`

禁止使用：

- `aria-label="settings"`
- `aria-label="config"`
- `aria-label="columns"`
- `aria-label="按钮"`
- 空 `aria-label`

## 6. 状态术语

### 6.1 通用界面状态

| 状态 | 推荐文案 | 说明 | 禁止混用 |
|---|---|---|---|
| 加载 | 加载中 | 页面级加载 | 读取中、处理中 |
| 保存中 | 保存中 | 表单保存请求中 | 提交中 |
| 提交中 | 提交中 | 流程提交请求中 | 保存中 |
| 处理中 | 处理中 | 后台任务执行中 | 执行中 |
| 已完成 | 已完成 | 任务完成 | 完成、成功 |
| 已取消 | 已取消 | 用户或系统取消 | 取消、关闭 |
| 已失败 | 已失败 | 任务失败状态 | 失败、异常 |
| 已启用 | 已启用 | 基础资料可用 | 开启、启用中 |
| 已停用 | 已停用 | 基础资料不可用 | 禁用、关闭 |
| 待审核 | 待审核 | 等待审核动作 | 待审、未审核 |
| 审核通过 | 审核通过 | 审核结果通过 | 已通过 |
| 审核驳回 | 审核驳回 | 审核结果驳回 | 已驳回 |

### 6.2 空态文案

空态文案应包含“当前状态 + 建议动作”。

推荐：

- “暂无数据”
- “暂无符合条件的数据，请调整筛选条件后重试。”
- “暂无可选记录，请先新增基础资料。”
- “暂无权限查看该数据，请联系管理员开通权限。”

禁止：

- “无”
- “空”
- “No Data”
- “暂无”
- “数据为空”

### 6.3 错误文案

错误文案应遵循“发生了什么 + 用户能做什么”的结构。

推荐：

- “数据加载失败，请刷新后重试。”
- “保存失败，请检查必填项后重试。”
- “导入失败，请下载失败明细并修正后重新导入。”
- “当前数据已被他人更新，请刷新后再操作。”

禁止：

- “Error”
- “失败”
- “系统异常”
- “请求错误”
- 直接展示接口堆栈或英文错误。

## 7. 权限术语

| 场景 | 推荐文案 | 说明 | 禁止混用 |
|---|---|---|---|
| 无页面权限 | 暂无页面访问权限 | 页面级权限不足 | 无权限、禁止访问 |
| 无数据权限 | 暂无该数据权限 | 行级或组织数据权限不足 | 不能查看、数据不可见 |
| 无操作权限 | 暂无操作权限 | 按钮或动作不可执行 | 无按钮权限、禁止操作 |
| 联系管理员 | 请联系管理员开通权限 | 建议动作 | 联系系统管理员、找管理员 |
| 权限变更后刷新 | 权限变更后请刷新页面 | 权限缓存提示 | 重新登录、刷新权限 |
| 角色 | 角色 | 权限分组对象 | 岗位、权限组 |
| 数据范围 | 数据范围 | 数据权限边界 | 数据权限、可见范围 |

### 7.1 权限提示规范

权限提示应避免责备用户，优先说明原因和下一步：

- 页面级：`暂无页面访问权限，请联系管理员开通权限。`
- 数据级：`暂无该数据权限，请切换数据范围或联系管理员。`
- 操作级：`暂无操作权限，请联系管理员开通后再试。`

禁止：

- “非法访问”
- “权限不足！”
- “Forbidden”
- “403” 直接作为页面主文案

## 8. 批量操作术语

| 场景 | 推荐文案 | 说明 | 禁止混用 |
|---|---|---|---|
| 批量入口 | 批量操作 | 工具栏分组 | 批处理、批量处理 |
| 批量审核 | 批量审核 | 对选中记录审核 | 批审 |
| 批量导出 | 批量导出 | 导出选中记录 | 导出选中、下载选中 |
| 批量标记 | 批量标记 | 给选中记录打标 | 批量打标、批量标签 |
| 批量取消 | 批量取消 | 取消未完成动作 | 批量关闭 |
| 批量作废 | 批量作废 | 使选中单据失效 | 批量取消、批量废弃 |
| 批量删除 | 批量删除 | 删除选中记录 | 批量移除 |
| 批量结果 | 批量操作结果 | 结果弹窗标题 | 处理结果 |
| 部分成功 | 部分成功 | 一部分成功、一部分失败 | 部分完成 |
| 失败明细 | 失败明细 | 失败记录列表 | 错误明细 |

### 8.1 批量操作确认文案

批量操作必须说明范围和后果：

- `已选 {count} 条，确认批量审核通过？`
- `已选 {count} 条，确认批量作废？作废后单据不可继续流转。`
- `已选 {count} 条，确认批量删除？删除后不可恢复。`
- `已选 {count} 条，确认批量导出？`

批量操作按钮不可在未选择数据时直接执行。未选择时提示统一为：

- `请先选择要操作的数据。`

| 导出选中记录 | 导出选中数据 | 仅导出勾选行 | 批量下载 |
| 导出全部权限内数据 | 导出全部数据 | 必须确认范围 | 全部导出 |
| 生成导出任务 | 生成导出任务 | 异步导出 | 创建任务 |
| 导出任务完成 | 导出完成 | 文件可下载 | 任务完成 |
| 下载导出文件 | 下载文件 | 下载生成文件 | 导出文件 |

### 9.3 导入导出提示规范

推荐：

- `导入前请先下载模板，并按模板填写数据。`
- `导入完成：成功 {successCount} 条，失败 {failureCount} 条。`
- `导出任务已生成，可在任务中心查看进度。`
- `当前导出数据较多，系统将生成导出任务。`

禁止：

- “上传成功”表示导入成功。
- “下载数据”表示导出。
- “导出模板”表示下载模板。

## 10. 设置页术语

| 场景 | 推荐文案 | 说明 | 禁止混用 |
|---|---|---|---|
| 页面标题 | 设置 | 设置类总入口 | 配置、参数 |
| 业务设置页 | 销售设置 / 系统设置 | 按模块命名 | 销售配置、系统参数 |
| 设置分区 | 基础设置 | 通用基础项 | 基本配置 |
| 开关项 | 启用 / 停用 | 业务规则状态 | 开启 / 关闭 |
| 保存设置 | 保存设置 | 设置页主按钮 | 保存配置、提交设置 |
| 重置设置 | 恢复默认 | 恢复系统默认配置 | 重置、初始化 |
| 校验设置 | 校验设置 | 检查配置正确性 | 验证、检查 |
| 变更摘要 | 变更摘要 | 展示本次修改项 | 修改明细、变化记录 |
| 未保存提示 | 存在未保存的设置 | 离开页面提示 | 有变更、未提交 |

### 10.1 设置页确认文案

- 保存：`确认保存当前设置？保存后将影响后续业务处理。`
- 恢复默认：`确认恢复默认设置？当前未保存的修改将被清除。`
- 离开页面：`存在未保存的设置，确认离开当前页面？`
- 停用规则：`确认停用该规则？停用后新业务将不再应用该规则。`

## 11. 危险操作文案规范

### 11.1 危险等级

| 等级 | 动作 | 视觉和文案要求 |
|---|---|---|
| 高风险 | 删除、批量删除、清空、覆盖、作废、批量作废 | 使用危险色；必须二次确认；确认按钮重复动作；说明不可恢复或业务影响 |
| 中风险 | 停用、取消、驳回、撤回、关闭任务 | 需要确认；说明影响范围；按钮使用明确动作词 |
| 低风险 | 重置筛选、恢复默认视图、刷新 | 可直接执行或轻提示；不得表现为数据删除 |

### 11.2 确认弹窗结构

危险操作确认弹窗统一包含：

1. 标题：`确认{动作}`，例如“确认删除”。
2. 内容：说明对象、数量、后果和是否可恢复。
3. 主按钮：重复危险动作，例如“确认删除”。
4. 次按钮：统一为“取消”。

推荐文案：

- `确认删除该记录？删除后不可恢复。`
- `确认批量删除已选 {count} 条记录？删除后不可恢复。`
- `确认作废该订单？作废后订单不可继续发货或审核。`
- `确认停用该规则？停用后新业务将不再应用该规则。`
- `确认清空当前筛选条件？已填写的筛选项将被清除。`

禁止文案：

- `确定？`
- `是否继续？`
- `确认操作？`
- `删除吗？`
- 主按钮只写“确定”。

### 11.3 成功和失败反馈

危险操作完成后必须反馈结果：

- 成功：`删除成功。`
- 批量成功：`批量删除成功，共处理 {count} 条。`
- 部分成功：`部分删除成功：成功 {successCount} 条，失败 {failureCount} 条，请查看失败明细。`
- 失败：`删除失败，请刷新后重试。`

## 12. aria-label 中文规范

### 12.1 基本格式

`aria-label` 应遵循“动作 + 对象 + 必要状态”的格式。

推荐：

- `打开功能搜索`
- `关闭功能搜索`
- `展开左侧筛选面板`
- `收起右侧详情面板`
- `刷新订单列表`
- `查询商品列表`
- `列设置`
- `打开列设置`
- `关闭列设置`
- `选择第 {rowIndex} 行`
- `取消选择第 {rowIndex} 行`
- `查看订单详情：{orderNo}`
- `删除商品：{productName}`

禁止：

- 英文：`search`、`close`、`settings`、`more`
- 模糊：`按钮`、`图标`、`操作`、`更多`
- 缺对象：`打开`、`关闭`、`查看`
- 与实际动作不一致：按钮显示“刷新”，`aria-label` 写“重新加载”。

### 12.2 图标按钮规范

图标按钮没有可见文字时，必须提供中文 `aria-label`。有可见文字时，`aria-label` 不应覆盖成不同含义。

常见图标按钮统一写法：

| 图标按钮 | 推荐 aria-label |
|---|---|
| 搜索图标 | 打开搜索 |
| 刷新图标 | 刷新当前数据 |
| 设置图标 | 列设置 |
| 更多图标 | 更多操作 |
| 关闭图标 | 关闭 |
| 展开图标 | 展开面板 |
| 收起图标 | 收起面板 |
| 删除图标 | 删除记录 |
| 编辑图标 | 编辑记录 |
| 查看图标 | 查看详情 |

### 12.3 动态对象规范

当按钮作用于具体对象时，应将对象名称或编号加入 `aria-label`：

- `查看订单详情：{orderNo}`
- `编辑商品：{productName}`
- `删除仓库：{warehouseName}`
- `停用角色：{roleName}`
- `下载导入失败明细：{taskNo}`

## 13. 后续可机器扫描建议

### 13.1 建议新增术语配置

建议新增机器可读配置，例如：

- `apps/erp-web/src/app/layout/uiTerminology.ts`
- `apps/erp-web/scripts/check-ui-terminology.mjs`
- `apps/erp-web/src/app/layout/uiTerminology.test.ts`

配置内容建议包括：

- 推荐动作词列表；
- 禁止混用词列表；
- 危险操作必须确认的词；
- `aria-label` 禁止英文和模糊词；
- 允许的业务例外清单；
- 页面级豁免原因。

### 13.2 建议扫描规则

| 规则 | 扫描目标 | 失败条件 | 例外 |
|---|---|---|---|
| 禁止用户可见英文动作词 | `.tsx`、`.ts`、测试快照 | 按钮、菜单、aria-label 出现 `Search`、`Refresh`、`Delete` 等 | 第三方组件内部不可控文案 |
| 禁止 Unicode 转义可见文案 | `.tsx`、`.ts` | 出现 CJK `\uXXXX` 字面量 | 正则、编码测试、技术字符 |
| 禁止混用查询与搜索 | 页面源码 | 同一列表页主查询按钮使用“搜索” | 功能搜索入口 |
| 禁止混用新增、新建、添加 | 页面源码 | 主创建按钮不使用“新增” | 添加已有对象到集合 |
| 危险操作必须确认 | 页面源码和测试 | 删除、作废、清空、覆盖没有确认文案 | 后端不可达的纯草稿撤销 |
| aria-label 必须中文 | `.tsx` | 图标按钮 aria-label 为英文、空值或模糊词 | 第三方库透传属性 |
| 列设置命名统一 | `.tsx` | 出现“字段设置”“列配置”“表头设置” | 技术文档和迁移说明 |
| 权限文案统一 | `.tsx` | 页面主文案直接显示 `403`、`Forbidden` | 路由状态码字段 |

### 13.3 建议扫描输出

扫描脚本应输出：

- 违规文件路径；
- 行号；
- 命中的原始文案；
- 推荐替换文案；
- 规则编号；
- 是否允许登记例外；
- 当前统一性得分影响。

示例输出：

```text
[UI_TERMS_001] 禁止混用“搜索”作为列表主查询按钮
文件：apps/erp-web/src/pages/orders/ExamplePage.tsx:120
当前：搜索
建议：查询
```

### 13.4 建议 CI 接入

建议新增命令：

```bash
pnpm --dir apps/erp-web run lint:ui-terms
pnpm --filter erp-web test:ui-contract
```

接入顺序建议：

1. 第一阶段只输出 warning 和报告；
2. 第二阶段对 P0 页面设为阻断；
3. 第三阶段对所有适用页面设为阻断；
4. 所有例外必须写明原因、负责人和清理期限。

### 13.5 基线评分脚本中的术语治理接入

当前 `assess:ui-uniformity` 已能输出模板、表格和页面结构相关基线。术语治理暂以本文档和 Code Review 为主，后续建议逐步接入脚本：

```bash
pnpm --dir apps/erp-web run assess:ui-uniformity
pnpm --dir apps/erp-web run assess:ui-uniformity -- --json
node apps/erp-web/scripts/assess-ui-uniformity.mjs --json
```

建议接入顺序：

1. 先扫描用户可见 Unicode 转义、替换字符和常见中文乱码。
2. 再扫描按钮高频混用词，例如“查询/搜索”“刷新/重新加载”“列设置/列配置”。
3. 再扫描危险操作确认文案，确保按钮不是单独的“确定”。
4. 最后将英文残留、缺失中文 `aria-label` 和状态提示纳入评分。

术语扫描进入 CI 前，应先以报告模式运行，确认误判可控后再升级为阻断门禁。

## 14. 术语例外登记规范

如果业务确实需要使用非推荐词，必须登记：

| 字段 | 说明 |
|---|---|
| 例外词 | 实际使用的词 |
| 推荐词 | 术语表推荐词 |
| 所属模块 | 订单、商品、仓储等 |
| 适用页面 | 具体页面路径 |
| 业务原因 | 为什么不能使用推荐词 |
| 有效期 | 临时例外必须有清理日期 |
| 负责人 | 业务或技术负责人 |

例外原则：

- 业务专有名词可以例外；
- 历史用户习惯可以短期例外；
- 技术字段名不应直接成为用户可见例外；
- 例外数量应随版本逐步减少，不得无期限扩张。

## 15. Code Review 检查清单

UI 相关 PR 需要逐项检查：

- 是否使用本文档推荐动作词；
- 是否存在“查询/搜索”“新增/新建/添加”“作废/取消/关闭”等混用；
- 表格空态、加载态、失败态是否统一；
- 表格列设置入口是否写为“列设置”；
- 批量操作是否显示已选数量；
- 危险操作是否二次确认并说明后果；
- 导入导出流程是否区分“下载模板、选择文件、上传文件、开始导入、导出”；
- 设置页是否使用“保存设置、恢复默认、变更摘要、存在未保存的设置”；
- `aria-label` 是否为中文且动作对象明确；
- 是否出现用户可见英文、乱码或 `\uXXXX` 转义；
- 是否需要登记术语例外。

## 16. 推荐落地顺序

1. 先将本文档作为人工 Code Review 标准。
2. 将“Unicode 转义可见文案”继续保持为阻断测试。
3. 新增术语扫描脚本，先对 P0 页面输出报告。
4. 对危险操作确认文案、`aria-label` 中文、列设置命名设置阻断规则。
5. 将禁止混用词逐步扩大到所有工作台页面。
6. 每次新增页面时同步更新术语例外或术语表。

## 17. 最小达标定义

一个 ERP 前端页面在术语层面达标，应满足：

- 主动作使用推荐动作词；
- 同一页面不混用同义词；
- 表格、列设置、状态、权限、批量操作、导入导出、设置页文案符合本文档；
- 危险操作有明确确认文案和后果说明；
- `aria-label` 使用中文且语义完整；
- 不显示英文占位词、乱码或 Unicode 转义；
- 如有业务特殊词，已登记例外。
