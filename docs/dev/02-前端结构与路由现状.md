# 前端结构与路由现状

> 范围：`apps/erp-web`

本文面向接手 Web 前端的开发者，重点说明：

- 前端代码如何分层
- 当前主路由实际开放了哪些入口
- 页面模板和工作台抽象大概是什么结构
- 接手一个页面时应该先看哪里

## 1. 前端入口与启动链路

应用启动链路比较清晰：

1. `src/main.tsx`
2. `src/app/AppProviders.tsx`
3. `src/app/router.tsx`
4. `src/app/layout/WorkbenchLayout.tsx`
5. 具体页面组件

`main.tsx` 只做三件核心事：

- 加载主题与 AG Grid 样式
- 注入全局 Provider
- 把 React Router 挂到根节点

因此，接手前端排查问题时，通常从 `router.tsx` 和 `WorkbenchLayout.tsx` 比从 `main.tsx` 更有效。

## 2. 目录分层

`apps/erp-web/src` 当前可以按职责大致理解为：

| 目录 | 作用 |
| --- | --- |
| `app` | 路由、全局 Provider、权限守卫、布局、导航与工作台壳层 |
| `api` | API 调用层、生成类型、Mock 数据、接口级测试 |
| `components` | 可复用组件、工作台模板、页面模板、数据表格封装 |
| `features` | 跨页面复用的业务能力，如租户、权限、打印、能力开关 |
| `pages` | 业务页面入口；数量很多，既有真实页面也有占位或渐进式接入页面 |
| `styles` | 主题与排版定义 |
| `utils` | 环境变量、错误处理、设备判断等通用工具 |
| `assets` | 图片、品牌资源等静态素材 |

## 3. 当前主路由实际开放的入口

截至 2026-04-25，`src/app/router.tsx` 当前主路由明确挂载的业务入口主要包括：

- `/dashboard`
- `/channels`
- `/channels/service-purchase`
- `/channels/authorize`
- `/couriers`
- `/tags`
- `/warehouses`
- `/logistics-fees`
- `/suppliers`
- `/sales/order-query`
- `/orders/review`
- `/orders/recheck`
- `/sales/settings`

配套的系统路由还包括：

- `/login`
- `/403`
- `/404`

这里要特别区分两件事：

1. `src/pages/` 下存在大量页面文件
2. 主路由当前只开放了一部分页面路径

也就是说，页面文件规模远大于菜单与主路由实际暴露范围。接手某个页面前，要先确认它是：

- 已挂到主路由的正式入口
- 仍在演进中的页面实现
- 仅供后续接入的占位页面

## 4. 菜单模型与页面开放范围

主菜单定义在 `src/app/layout/menu.tsx`，当前顶层菜单主要是：

- 首页
- 目录
- 销售

其中已经明确收敛到的核心业务入口有：

- 渠道目录
- 物流目录
- 标签目录
- 仓库目录
- 供应商目录
- 订单查询
- 订单审核
- 订单复核
- 销售设置

这说明当前前端主导航仍然偏“收束式开放”，而不是把全部已实现页面一次性暴露出去。

## 5. 前端里最值得先理解的几层抽象

### 5.1 应用壳层

优先看这些文件：

- `src/app/router.tsx`
- `src/app/layout/WorkbenchLayout.tsx`
- `src/app/layout/menu.tsx`
- `src/app/guards/*.tsx`

它们决定了：

- 页面怎么进
- 权限怎么拦
- 工作台壳子怎么装配
- 顶部菜单、标签页、快捷入口怎么组织

### 5.2 工作台与模板层

仓库内可以看到两组明显的可复用工作台抽象：

- `src/components/page-templates/workbench/`
- `src/components/workbench/templates/`

此外还有一组更细粒度的 UI 模块：

- `src/components/ui-modules/`

这意味着接手工作台类页面时，要先分辨目标页面跟随的是哪条抽象链路，避免把不同模板体系混在一起改。

### 5.3 页面共享逻辑

订单工作台相关的共享逻辑集中在：

- `src/pages/orders/shared/`
- `src/pages/orders/review-native/`
- `src/pages/orders/exceptions-native/`

这部分通常比单页组件更值得先读，因为很多表格行为、选择逻辑、筛选器和动作守卫都沉在共享目录。

## 6. API、Mock 与契约生成

前端 API 层大致分三块：

1. `src/api/generated/schema.ts`
   来自 `openapi/erp_api_v1.yaml` 生成的类型

2. `src/api/*.ts`
   每个业务域的 API 封装

3. `src/api/mocks/*`
   前端单独开发时使用的 Mock 数据与契约测试

常见命令：

```bash
pnpm --dir apps/erp-web run generate:api
pnpm --filter erp-web test:unit
pnpm --filter erp-web test:e2e
```

如果接手的页面接口行为不稳定，建议先确认三件事是否一致：

- `openapi/erp_api_v1.yaml`
- `src/api/*.ts`
- 目标页面实际消费的数据结构

## 7. 测试与构建入口

前端常用命令主要集中在 `apps/erp-web/package.json`：

- `pnpm --filter erp-web dev`
- `pnpm --filter erp-web build`
- `pnpm --filter erp-web lint`
- `pnpm --filter erp-web typecheck`
- `pnpm --filter erp-web test:unit`
- `pnpm --filter erp-web test:e2e`

仓库根目录还提供了统一门禁命令：

```bash
pnpm run accept:web
pnpm run accept:all
```

## 8. 接手一个前端页面时的推荐阅读顺序

建议按下面的顺序切入：

1. 先看 `src/app/router.tsx`，确认页面是否真的挂到了主路由
2. 再看 `src/app/layout/menu.tsx`，确认它是否在当前导航体系中
3. 找到对应 `src/pages/...` 页面入口
4. 倒查它依赖的是哪套工作台模板或共享模块
5. 查看对应的 `src/api/*.ts`
6. 查看关联测试和 Mock

如果目标是订单、渠道、商品下载、销售设置这类工作台页面，通常不要只盯着页面组件本身，应该优先理解它绑定的模板与共享模型。

## 9. 当前前端最重要的接手结论

1. 前端代码量已经很大，但主路由和主菜单仍然是收敛开放状态。
2. 页面模板与工作台抽象不是单一体系，接手前需要先识别当前页面所处的模板线。
3. API 层、Mock 层和页面层都比较完整，排查问题时应该三者一起看，而不是只看页面。
