# ERP 前端中文与编码约束

## 目标

- 保证 ERP 项目中所有面向用户与面向开发者的中文内容可读、统一、可回归。
- 避免因复制外部文本、错误编码保存、终端转码等问题引入乱码。
- 将中文文案收口到共享模板、共享常量或明确的业务模块中，减少散落硬编码。

## 适用范围

- Web 前端页面 UI 文案
- 表格列名、筛选项、空状态、提示语、按钮文案
- 用户可见日志、消息提示、弹窗文案
- E2E / 单测用例标题与断言文本
- 本次修改涉及文件中的注释与开发文档

## 强制规则

1. 所有新建或修改的前端源码文件，统一使用 `UTF-8` 保存。
2. 所有用户可见文案必须使用简体中文，不允许提交乱码、半截转码文本或不可读占位文本。
3. 共享模板中的公共文案优先收口到模板常量，不要在多个页面重复硬编码。
4. 测试标题、测试描述、空状态断言文案优先使用中文，保持和实际 UI 语义一致。
5. 错误提示、操作反馈、导出/打印失败等消息必须是中文，且表达清楚业务动作与失败原因。
6. 复制外部文案后，提交前必须在浏览器页面或测试输出里实际确认一次，没有出现乱码再合并。

## 推荐做法

- 左侧筛选、统计区、主表工具栏、底部分页等公共区域，优先在共享模板中定义中文文案。
- 页面级特殊文案，只保留在对应业务模块，不要散落到多个 hook 或测试中。
- 如果一个文案会被多个页面复用，优先抽成共享常量或模板 props。
- 空状态文案统一使用清晰中文，例如 `暂无数据`、`无匹配项`、`暂无订单`。

## 禁止事项

- 禁止提交类似 `杩囨护`、`缁熻`、`\uFFFD\uFFFD\uFFFD` 这类明显错误转码文本。
- 禁止在同一模块中混用中文、英文和转码残片描述同一概念。
- 禁止为了图省事，将用户可见文案写成英文占位后续再补。

## 提交前检查

1. 运行受影响页面，人工确认关键文案是否正常显示。
2. 运行相关单测 / E2E，确认断言文本与界面文案一致。
3. 搜索本次改动文件中是否存在明显乱码特征，例如 `\uFFFD\uFFFD\uFFFD`、`杩`、`缁`、`锛`。
4. 对共享模板修改时，同时检查至少一个实际业务页，避免模板正常而页面传参仍是乱码。

## 当前已落地约束点

- 订单左侧筛选与统计模板统一使用共享中文文案。
- 订单左侧过滤模块默认空状态统一为 `无匹配项`。
- 订单主表多选与自由框选交互统一收口到 `orders/shared` 共享层，后续页面复用同一套体验约束。
