# 策略设置 UI 布局重规划（预览稿）

## 1. 目标与范围

- 目标：重建“有主数据表的设置页”基础骨架，形成统一、紧凑、企业级电商 ERP 风格。
- 适用页面：销售策略设置及同类“策略清单 + 配置明细 + 子表”的页面。
- 设计基线：参照订单审核的 Workbench 交互能力，结合销售设置页的目录化体验。

## 2. 方案对比（含推荐）

### 方案 A（推荐）：Workbench 四模块并列骨架

- 结构：左树目录 + 主表区 + 右动作面板 + 底部子表。
- 优点：扩展性最好，和订单审核交互模型一致，迁移成本低。
- 风险：初次重构需要梳理现有页面状态管理。

### 方案 B：双栏主区 + 弹层子表

- 结构：左目录 + 主表，右侧动作用 Drawer，底部子表改弹层。
- 优点：首屏更宽，改动面少。
- 风险：高频查看子表时操作链路变长，不适合连续审阅。

### 方案 C：单栏流式设置页 + 内嵌表格

- 结构：保留销售设置页纵向卡片，表格与子表嵌在卡片中。
- 优点：视觉统一简单。
- 风险：不适合大数据量与批量操作，和订单审核风格差异大。

结论：推荐 **方案 A** 作为策略设置页工业化模板。

## 4. 四模块定义（紧凑版）

### 模块 1：左侧 ERPDATAGRID 树形目录与树形搜索

- 作用：提供“策略分类 + 节点检索 + 节点统计”，替代传统纯按钮导航。
- 关键点：
- 搜索支持路径命中（父/子节点联动高亮）。
- 节点支持计数徽标（总数、启用数、异常数）。
- 节点切换只更新查询条件，不重置用户列配置。

### 模块 2：右侧批量操作面板（全选/反选/快捷修改）

- 作用：集中承载批量动作，避免散落在工具栏。
- 关键点：
- 三段式：选择控制区、快捷修改区、结果反馈区。
- 全选分为“当前页全选”和“查询结果全选”。
- 快捷修改必须先展示“影响条数预估”。

### 模块 3：主数据表（分页统计 + 滚动条吸附规则）

- 作用：作为策略主操作区，承载筛选、编辑入口、状态展示。
- 关键点：
- 表格启用紧凑密度，行高建议 30-32。
- 分页统计固定在主表底部。
- 吸附规则：
- 当底部子表可见时，主表滚动条吸附到子表上边缘。
- 当底部子表隐藏/无数据时，主表滚动条吸附到页面底部。

### 模块 4：底部子表

- 作用：显示当前策略行的扩展信息（条件、执行轨迹、日志）。
- 关键点：
- Tab 最多 4-5 个，避免信息过载。
- 支持“跟随主表行变更自动刷新”，但保留手动刷新按钮。
- 默认高度 240，允许拖拽到 360。

## 5. 紧凑化标准（企业 ERP）

- 栅格间距：主间距 8，区块间距 12（替代 16）。
- 卡片内边距：12（替代 16/20）。
- 按钮高度：28；输入框高度：28。
- 表头高度：32；表体行高：30-32。
- 字号：主内容 12/13，标题 14/16。

## 6. 尺寸建议（桌面端）

- 左侧树模块宽度：220（可拉伸 200-300）。
- 右侧操作模块宽度：260（可拉伸 240-320）。
- 底部子表高度：240（最小 180，最大 360）。
- 主表保底可视宽度：980。

## 7. 销售策略设置页映射

- 原左侧策略导航卡片 -> 模块 1 树目录。
- 原中部策略列表 -> 模块 3 主数据表。
- 原弹窗内批量动作前置 -> 模块 2 右侧批量操作。
- 原条件/排除条件明细 -> 模块 4 底部子表 Tab。

## 8. 工业化重构切分（后续实施）

- 第 1 步：抽象 `StrategyWorkbenchLayout`（四模块容器 + 状态同步）。
- 第 2 步：迁移 `SalesStrategySettingsPage` 到新骨架，保留既有业务字段。
- 第 3 步：统一分页统计、选择状态、快捷修改 API。
- 第 4 步：补充 E2E（树搜索、全选/反选、快捷修改、子表联动）。

## 9. 预览确认项

- 是否确认采用方案 A 作为统一模板。
- 左/右/底部默认尺寸是否按建议值。
- 子表默认 Tab 顺序是否按“命中条件 -> 排除条件 -> 执行记录 -> 变更日志”。
