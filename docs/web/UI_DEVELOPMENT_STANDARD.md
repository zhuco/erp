# ERP Web UI 开发规范

- 文档状态：`ACTIVE`
- 生效日期：`2026-04-19`
- 适用范围：`apps/erp-web/src/**`
- 正式标准：主数据工作台页面统一纳入 **一体化数据作业台** 体系，替换现有分叉工作台思路

## 1. 唯一入口与正式命名

本文件是 ERP Web UI 的唯一长期规范入口。

面向“主数据工作台页面”的正式中文名称统一为：

- **一体化数据作业台**

该名称用于替代宽泛的 `Workbench`、`数据表工作台`、`订单工作台` 等历史表达。后续产品文案、设计评审、研发协作和技术规范统一使用该中文名称。

迁移期允许保留以下代码兼容入口：

1. `WorkbenchPageTemplate`
2. `WorkbenchToolbar`

以下名称只允许作为历史术语或过渡兼容描述出现，不再作为长期规范入口：

1. `WorkbenchMainTableTemplate`
2. `WorkbenchToolbarTemplate`
3. `review / recheck / query` 三分叉主表路线
4. 页面自行拼接主表交互逻辑的实现方式

## 2. 长期页面家族

ERP Web 当前只保留两类长期页面家族：

1. 一体化数据作业台
2. 设置型页面

其中：

1. 一体化数据作业台用于所有“以中央主数据表为核心”的页面。
2. 设置型页面继续使用 `SettingsPageTemplate` 与 `SettingsPageSection` 体系。

本次工作台改造聚焦第一类。

## 3. 工业级目标

一体化数据作业台不是“统一页面壳子”的轻量约定，而是面向企业级电商 ERP 的统一交互内核标准。其目标必须同时满足：

1. 新建页面时，开发者不再手写主表选择逻辑、左右联动、子表联动、列筛选、状态恢复。
2. 页面之间的差异只体现在数据范围、业务动作、字段定义和业务语义上。
3. 用户在审核、复核、查询、商品、渠道、库存等页面之间切换时，不需要重新学习基础交互。
4. 与数据无关的通用能力必须集中治理，包括搜索、导出、打印、帮助、保存视图、分页恢复、列配置、详情联动和子表联动。
5. 页面实现方式必须从“复制旧页面结构”升级为“适配器 + schema 的配置式接入”。

## 4. 适用范围与标准布局

以下页面必须纳入一体化数据作业台体系：

1. 页面核心是中央主数据表。
2. 页面具备顶部工具栏。
3. 页面需要左侧过滤、右侧详情、底部子表中的一种或多种组合。
4. 页面存在批量处理、主表选择、列筛选、详情联动、上下文切换等高频操作。

一体化数据作业台的标准结构固定为：

1. 顶部工具栏
2. 左侧过滤
3. 中央主表
4. 右侧详情
5. 底部子表

其中右侧详情和底部子表允许按页面场景隐藏，但隐藏必须通过统一内核的能力裁剪完成，而不是重新建立另一套页面模板。

## 5. 三层架构标准

### 5.1 骨架层

骨架层负责统一页面布局、区域挂载和基础视觉节奏，不承载业务语义。

当前代码兼容入口为：

1. `apps/erp-web/src/components/page-templates/workbench/WorkbenchPageTemplate.tsx`
2. `apps/erp-web/src/components/page-templates/workbench/WorkbenchToolbar.tsx`

骨架层职责只包括：

1. 顶部工具栏区域挂载
2. 左侧过滤区域挂载
3. 中央主表容器挂载
4. 右侧详情容器挂载
5. 底部子表容器挂载
6. 页面节奏、字号和容器层级

### 5.2 统一内核层

统一内核层是一体化数据作业台的核心，后续实现应逐步收敛为统一的工作台内核，例如：

1. `DataWorkbenchKernel`
2. `DataWorkbenchMainGrid`
3. `DataWorkbenchRightPanel`
4. `DataWorkbenchBottomTabs`

统一内核必须集中承担以下能力：

1. 主表实现路线
2. 行选择与多选逻辑
3. 焦点记录逻辑
4. 列筛选与列配置
5. 保存视图与工作台状态恢复
6. 右侧详情联动
7. 底部子表联动
8. 搜索、导出、打印、帮助等工具栏标准动作
9. 加载态、空态、错误态

页面层不得再自行选择另一套主表实现路线。

### 5.3 页面配置层

页面配置层负责把具体业务接入统一内核。页面只允许通过以下契约声明业务差异：

1. 数据适配器
2. 左侧过滤 schema
3. 主表列 schema
4. 工具栏业务动作 schema
5. 右侧详情 schema
6. 底部子表 schema

## 6. 页面只允许声明的业务差异

一体化数据作业台接入页面时，页面层只负责声明业务内容，不负责重写基础交互。

页面层允许声明：

1. 数据范围，例如待审核、待复核、全部订单。
2. 左侧过滤维度与统计口径。
3. 主表字段、列顺序和字段渲染。
4. 页面业务动作，例如审核、拆单、合单、复核、标记。
5. 右侧详情字段与展示分组。
6. 底部子表类型与标签定义。

其中“审核 / 拆单 / 合单”等业务动作继续留在页面配置层，但必须插入统一工具栏动作区，不得重新发明一套工具栏或主表交互。

## 7. 统一交互标准

### 7.1 顶部工具栏

所有一体化数据作业台页面必须具备统一工具栏规则：

1. 搜索、导出、打印、帮助位置一致。
2. 页面业务动作只允许插入统一动作区。
3. 不允许页面重新定义另一套 toolbar shell。

### 7.2 左侧过滤

左侧过滤必须由统一契约驱动，至少统一以下规则：

1. 过滤分组、节点层级、统计项和筛选表单使用统一节奏与字号。
2. 节点点击如何映射为查询条件由 schema 定义，不由页面零散拼接。
3. 过滤状态在分页、详情切换、标签切换后保持一致。

### 7.3 中央主表

中央主表必须统一为同一实现路线，至少统一以下规则：

1. 选择列样式一致。
2. 单选、多选、全选规则一致。
3. 焦点记录规则一致。
4. 列筛选入口、列配置入口和保存视图能力一致。
5. 双击行为、上下文菜单和滚动反馈一致。
6. 加载态、空态、错误态反馈一致。

### 7.4 右侧详情

右侧详情必须统一以下联动规则：

1. 主表焦点变化后自动刷新详情。
2. 无焦点记录时统一空态。
3. 加载中与失败反馈口径一致。
4. 记号区、详情节奏和轻量工具区遵循统一布局标准。

### 7.5 底部子表

底部子表必须统一以下联动规则：

1. 主表焦点变化后自动刷新子表。
2. 子表 tab 样式、切换位置和加载反馈一致。
3. 无焦点记录时统一空态。

### 7.6 状态恢复

统一内核必须支持集中保存并恢复以下状态：

1. 搜索值
2. 左侧过滤状态
3. 主表列筛选状态
4. 选中记录与焦点记录
5. 分页状态
6. 右侧详情与底部子表显隐状态

## 8. 统一字号与视觉节奏

唯一字号配置入口：

1. `apps/erp-web/src/styles/typography.ts`

统一变量入口：

1. `--erp-font-size-body`
2. `--erp-font-size-body-strong`
3. `--erp-font-size-title`
4. `--erp-font-size-title-display`

默认层级：

1. 正文：`12.8px`
2. 区块标题：`15px`
3. 页面级主标题：`18px`

强制规则：

1. 左侧过滤项、表格正文、输入控件、按钮文案、说明文本统一使用正文层级。
2. 工具栏标题、面板标题、区块标题统一使用标题层级。
3. `18px` 只作为页面级保留层级，不允许在普通工作台页面多处滥用。
4. `WorkbenchPageTemplate` 与 AG Grid 的正文字号必须同源。
5. 不允许在共享模板覆盖范围内继续写死新的普通字号。

## 9. 实施与迁移规则

一体化数据作业台的实施原则如下：

1. 新页面必须通过“数据适配器 + schema 配置”接入，不再手写主表交互控制器。
2. 页面如果隐藏右侧详情或底部子表，只能通过统一配置开关完成。
3. 修改高频工作台页面时，优先改共享骨架与统一内核，不优先堆页面补丁。
4. 旧的 `review / recheck / query` 路线只允许作为迁移期兼容存在，不再继续扩张。
5. 不再新增新的页面级主表模板。
6. 不再新增新的工作台主表实现路线。

## 10. 测试与门禁

涉及一体化数据作业台骨架、字号、主表交互或区域联动时，至少补齐与改动范围对应的单测和 E2E。

当前代表性验证命令包括：

1. `pnpm test:unit -- src/app/themeTypographyConfig.test.ts`
2. `pnpm test:unit -- src/components/workbench/templates/OrderReviewWorkbenchTemplate.typography.test.ts`
3. `pnpm test:unit -- src/components/ui-modules/UiModule07SettingsLayout.typography.test.ts`
4. `pnpm exec playwright test e2e/workbench-typography.spec.ts --project=chromium`
5. `pnpm playwright test e2e/workbench-main-table-visibility.spec.ts --project=chromium`
6. `pnpm playwright test e2e/order-workbench-pages.spec.ts --project=chromium`

如改动触及统一内核控制器、列配置、选择逻辑或状态恢复，还必须补对应的控制器级单测。

## 11. 文档维护规则

1. 工作台标准发生变化时，先更新本文件，再提交实现。
2. `docs/spec/erp-feature-catalog/16-开发协作与前端规范.md` 只保留协作入口与指针，不再复制完整 UI 细则。
3. 偏离一体化数据作业台标准的页面，必须先补设计文档并写清偏离原因与适用范围。
4. 不再新增并行的“临时工作台规范文档”作为长期入口。
