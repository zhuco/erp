# DR Runbook（灾备与恢复）

## 1. 目标

- RPO：15 分钟
- RTO：60 分钟
- 覆盖范围：Postgres、NATS、对象存储、ClickHouse（可选）、关键配置与密钥

## 2. 备份策略

1. Postgres
- 全量备份：每日 02:00
- WAL 归档：持续
- 保留周期：30 天

2. 配置与密钥
- `.env`/密钥管理系统：每日导出只读快照
- 租户配置（settings）随数据库备份

3. 对象存储
- 启用版本控制与跨可用区复制

## 3. 故障分级

1. P1（全站不可用）
- 触发条件：核心 API 不可达或数据库不可写
- 处置：立即执行主备切换流程

2. P2（核心链路受损）
- 触发条件：OMS/WMS/财务关键接口错误率 > 20%
- 处置：回滚最近变更 + 降级非关键功能

## 4. 恢复流程

1. 确认故障范围并冻结发布
2. 选择恢复点（最近可用备份 + WAL）
3. 恢复数据库到新实例并执行一致性校验
4. 切流并验证关键业务链路
- 平台拉单
- OMS 审核
- WMS 发运
- 售后逆向
- 计划执行
5. 解除冻结，进入观察期 2 小时

## 5. 验证清单

- API 健康检查 `200`
- 队列消费延迟恢复到基线
- 关键业务 E2E 通过
- 告警恢复到正常阈值

## 6. 演练要求

- 每季度至少一次全链路演练
- 演练后 48 小时内输出复盘报告
