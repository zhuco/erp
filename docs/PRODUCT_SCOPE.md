## 产品定位

### 2026-10-01 制造与贸易免费在线 ERP

最新产品目标为“易格”：面向生产制造和贸易公司，官方提供免费在线服务，先扩大使用，后续增加收费功能。同一产品共享主数据、采购、库存、销售和往来款，制造增加 BOM、工艺、MRP、生产执行、质量追溯及生产成本。

免费版只允许一个可登录的使用者账号。2026-10-01 开发前已采用推荐策略：同一账号允许多端同时在线，单会话只保留为未启用的备选。账号席位与会话数分别建模，多人协作及高级业务能力作为后续收费方向。基础闭环、安全、服务方备份和基础数据导出保持免费。

功能及验收细目见用户要求建立的长期清单 [免费 ERP 功能及验收清单](FREE_ERP_CHECKLIST.md)，实施顺序与进度仍统一在 [路线图](ROADMAP.md)。本方向优先于下方旧阶段的电商自用及 SaaS 后置安排；Rust 双端、自研 DataGrid、通用模块优先、数据保护和统一构建约束继续有效。清单包含100项功能的字段、页面操作、实施接线、失败断言、现有/规划代码位置和量化门禁；16个开发任务包、14项共享库存入口、16个业务样本、核心表单类型/校验、当前制造实际路由/参数及14组完整制造查询目标，以及查询索引、性能负载/资源预算与结项格式。制造路由数量随接线变化，以第二十九节最新源码盘点及对应输入SHA为准。第三十一节另列8个实际销售路径/11个HTTP操作（含退货GET），以及贸易、单账号多端、MRP的逐函数接线与测试任务。性能目标与已有测量结果分别记录；实现和部分验收结果以路线图及独立证据为准，范围定义不代表上线已经完成。

### 历史交付边界 2026-09-09

- 当前没有用户，以业余开发和自用为主。全部新 UI 使用 Rust：原生桌面与 WASM Web 共享 egui 界面和网格，两端均需真实闭环验收；旧 React 页面只作需求参考，不要求逐页复刻。
- 第一阶段只围绕自己的店铺达到日常实用，以实际平台、岗位和操作流程确定范围；先收敛自研网格、查询与保存视图、业务对象选择器、批量操作反馈、详情与编辑面板五类组件，每类必须有真实页面验收。
- 易格先达到 ERP 可用组件标准，再铺开业务页面：日常查询/选择/编辑、服务端分页与跨页勾选、分组树形、报表透视/基础图表、计算列和高级导出均进入组件建设范围。用三个代表性业务夹具独立验收，再在最小业务宿主中验证真实 API，避免把整套 ERP UI 当作组件开发前置。此为目标范围，不表示当前实验台已具备这些能力。
- 第二阶段邀请 3—5 家商家试用，保持同一代码版本，优先独立部署和数据库；补足数据边界、备份恢复、安装升级和问题定位，不为每家维护分叉。
- 第三阶段在形成稳定收入后再建设 SaaS 自助开通、计费、配额和集中运维。下文完整 P0 可收费范围及 P1/P2 属于长期产品目录，不是第一阶段全部前置项。
- 自用阶段仍保留商家/店铺归属、权限、幂等、库存台账和操作日志；不通过删除数据边界来降低复杂度。
- 数据网格全面自研，禁止 AG Grid 社区版和企业版；详细功能边界见 [组件库规范](UI_COMPONENT_LIBRARY.md)，实施先后见 [路线图](ROADMAP.md)。

衡策云是面向多平台电商经营的工业级 ERP，服务多店铺、多仓、多角色、多组织协同场景。系统以平台订单为事实源，在 ERP 内完成订单审核、库存占用、仓储履约、物流发货、售后逆向、财务对账、经营分析和审计追踪。

项目不是单纯的后台菜单集合，也不是只用于演示的页面原型。目标产品必须支撑真实经营、稳定上线、可审计追溯、权限隔离和持续迭代。

## 设计原则

- 平台订单为准：外部平台状态是事实源，ERP 做增强、编排、补偿与审计。
- 闭环优先：每个核心单据都要有来源、状态、责任人、时间、动作日志和上下游影响。
- 配置优先：权限、审批、字段、编号、规则、策略和流程尽量配置化，避免散落在页面逻辑中。
- 工作台优先：核心岗位围绕待办、异常、批量处理、明细联动和结果反馈设计，不以菜单堆砌为目标。
- 工业化门禁：上线以 OpenAPI、数据库迁移、集成测试、E2E、审计、告警和发布门禁为准。

## P0：首个可收费试点版必须具备

- 店铺接入：至少一个平台能完成授权、Webhook 或订单下载、字段映射和失败重试。
- 订单闭环：订单进入系统后可审核、驳回、异常挂起、分配履约、发货并追踪状态。
- 库存闭环：库存可查询、预占、锁定、扣减，关键变更写入台账。
- 出库闭环：出库单、拣货、复核、打包、打印、发货至少形成可运行主链路。
- 商品闭环：SKU、渠道商品、条码、单位、套装和映射关系可维护并被订单使用。
- 售后闭环：至少支持退款或退货中的一条路径，并能关联订单、库存和财务差异。
- 基础财务：支持平台账单或订单金额的基础对账、差异记录和结算状态。
- 权限审计：运营、仓库、采购、财务、管理员至少具备基础角色区分，关键动作有审计日志。
- 门禁验收：OpenAPI、迁移、后端测试、前端构建、关键 E2E、Release Gate 和安全检查可执行。

- 多商户、多组织、多仓、多店铺的业务归属、数据权限和结算边界。
- 采购申请、采购订单、收货、入库、供应商对账的完整闭环。
- 安全库存、补货建议、调拨建议和库存风险预警。
- 客户 360、售后举证、退款回写、逆向质检和客服任务协同。
- 业务审批中心、异常中心、操作任务中心和通知中心。
- 财务应收应付、成本核算、利润分析、发票和回款闭环。
- 经营驾驶舱、钻取报表、导出治理和关键 SLA 报告。

## P2：工业化平台版本增强

- 私有化、专有云、SaaS 多租户的差异化部署与配置体系。
- 多法人、多公司、多事业部经营模型和跨组织流程路由。
- 开放平台、外部 API、字段映射市场、Webhook 订阅和伙伴集成。
- 行业化能力包，例如食品效期、服饰颜色尺码矩阵、序列号追溯和质量管理。
- 自动化补偿、智能异常归因、经营预测、动态补货和利润优化。
