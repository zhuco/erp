# ERP UI 旧代码对照与迁移纠偏

## 最新实施边界：先模块，再示例页（用户纠正）

用户明确：先独立打磨左侧树形筛选、顶部菜单、多标签、工具栏、主数据表、底部子表、右侧详情模块，再用示例数据拼成一个页面；当前不直接推进真实业务页面和业务接口。此要求优先于下文此前的订单查询业务接入顺序。

- 旧代码用于核对模块行为，`销售-网店订单查询.png` 用于校准紧凑浅灰布局、字体与表格密度。
- 主表和子表继续复用 DataGrid，不重写网格。其他模块先作为 workspace 内部 UI 模块，不拆成七套独立技术库。
- 示例宿主提供菜单项、树节点、列、行、详情字段和示例动作；模块通过稳定 ID 与事件协作，不反向依赖订单/商品页面或调用业务 HTTP。
- 示例页验证菜单打开/定位标签、标签状态隔离、树筛选、工具栏作用对象、主从表联动、右侧详情联动及面板尺寸保持。真实订单权限、标记接口、店铺上线和业务闭环不作为本轮模块收尾条件。
- 本轮开始但未完成的订单标记替换接口已收回；既有业务验收宿主代码保留，不等于新模块示例页已经完成。

2026-09-11。用户最新要求：旧代码对比优先；呈现参考 `docs/img/销售-网店订单查询.png` 的浅灰紧凑工具栏、左侧树形过滤与密集表格。其他截图用于辅助核对，不混用为同一版规格。

## 当前结论

当前 Rust 页面是网格验收宿主加应用外壳，不能称为旧 ERP UI 的完整迁移。此前的“完成工作台调整”仅能说明导航、面板和基础保存已接通，不能覆盖旧页面字段、动作、模块及接口行为。后续以旧路由的真实组件调用链逐页建立对应关系，而不是把实验台功能重新排列后当作业务页面。

## 旧实现也要纠正的部分

- `GoodsProductsQueryPage.tsx` 使用 `listProducts(...limit:500)` 后本地统计、筛选、分页。保留业务过滤含义，但不能复制500条截断后冒充全量查询。
- `OrderReviewPage.tsx:765` 有按需触发的全量扫描过滤路径。迁移应对接服务端谓词/聚合，不能为了外观一致退回无界全量加载。
- 旧页面说明、空插图、快捷搜索展开开关与后续用户约束冲突时，以用户新约束为准：紧凑、无常驻介绍、快速搜索始终展示、修改自动查询。
- 不恢复 AG Grid、Ant Design Table 或旧 React 运行时；迁移的是页面行为和数据契约，由 Rust 与 DataGrid 实现。

## 后续实施基线

1. 按旧路由建立“页面→主列→左过滤→右详情→底部Tab→操作→API”清单，逐项标记已迁移/缺失/旧占位/与新约束冲突。
2. 首先对齐用户选定的订单查询工作台，对照 `SalesOrderQueryWorkbenchPage` 及其实际调用组件；订单审核另列，不能混成一个页面。
3. 校准查询DTO、详情DTO与动作适配，再恢复模块。缺后端字段或接口时明确记录阻塞点，不靠虚构数据和空按钮填满布局。
4. 外观按照选定截图统一密度、工具栏、细网格线和左树，但字段、行为和模块归属以旧代码为依据。
5. 验收以具体旧业务动作在Rust中的对应结果为准；仅有相同区域、编译通过或通用网格能力不能记作整页迁移完成。
