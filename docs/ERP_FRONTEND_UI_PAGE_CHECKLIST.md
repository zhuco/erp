# ERP 前端 UI 新页面接入 Checklist

> **用途：** 用于新增或改造 ERP 前端页面时的 Code Review 检查。  
> **适用范围：** `apps/erp-web` 下业务工作台、列表页、目录页、查询页、设置页、详情页、编辑页、报表页和特殊豁免页面。  
> **目标：** 新页面默认进入统一模板、统一交互、统一文案、统一测试和统一门禁体系，持续降低 ERP 用户跨模块学习成本。  
> **依据：** `docs/ERP_FRONTEND_UI_UNIFORMITY_PLAN.md`。

---

## 1. 使用方式

- [ ] PR 描述中说明本次页面类型、所属模块、是否为 P0/P1/P2 页面。
- [ ] Reviewer 按本文逐项核对，不能满足的条目必须写明原因。
- [ ] 涉及豁免时，必须补充豁免登记，不能用口头说明替代。
- [ ] 涉及模板、工具栏、表格、状态、文案、a11y 或测试门禁的公共能力时，优先改共享组件，不在单页重复实现。
- [ ] 本清单默认适用于新增页面；改造旧页面时至少覆盖本次变更影响的区域，并不得引入新的统一性倒退。

## 2. 页面类型选择

### 2.1 类型判定

- [ ] 已明确页面属于以下哪一类：工作台列表页、主从工作台页、目录/基础资料页、设置页、创建/编辑页、详情阅读页、指标看板页、异常/登录/特殊页。
- [ ] 工作台列表页、主从工作台页、目录/基础资料页优先使用统一工作台模板。
- [ ] 设置页优先使用设置类模板，不强行套用列表工作台模板。
- [ ] 创建/编辑页优先使用编辑器类模板或既有表单模板，不复制工作台骨架。
- [ ] 详情阅读页优先使用详情阅读模板或统一详情区，不把详情页做成独立风格。
- [ ] 指标看板页优先使用指标看板模板，仍需遵守顶部导航、文案、状态和 a11y 标准。
- [ ] 登录页、异常页、临时诊断页等特殊页必须明确是否进入豁免登记。

### 2.2 页面优先级

- [ ] 已标注页面优先级：P0 高频核心页、P1 中频业务页、P2 低频或特殊页。
- [ ] P0 页面必须满足统一模板、统一工具栏、统一搜索、统一表格、统一状态、基础键盘可用和测试覆盖。
- [ ] P1 页面至少满足模板接入、主操作入口一致、表格体验不明显偏离和静态契约检查。
- [ ] P2 页面允许使用专用模板或豁免，但不得复制工作台布局，也不得出现乱码、英文残留或无说明的 UI 方言。

### 2.3 路由与菜单

- [ ] 页面路由已接入统一菜单、权限和面包屑或标签页体系。
- [ ] 菜单名称、页面标题、浏览器标题和功能搜索名称保持一致。
- [ ] 菜单叶子节点打开后不是空白页、占位页或未接入权限的裸页面。
- [ ] 页面关闭、返回、切换标签页时不丢失必要的筛选、分页和视图状态。

## 3. 模板接入

### 3.1 工作台模板

- [ ] 工作台类页面通过 `WorkbenchPageTemplate` 或项目认可的统一封装进入。
- [ ] 工业级复杂页面通过 `IndustrialWorkbenchTemplate` 或其上层封装承载骨架。
- [ ] 页面没有自定义复制顶部工具区、主表区、左右面板、底部面板、分页和滚动条骨架。
- [ ] 页面只替换业务适配点：数据源、列定义、搜索项、工具栏按钮、面板内容、标题和业务文案。
- [ ] 不新增绕过模板的布局容器、页面级 Card 堆叠或散落式工具栏。
- [ ] 使用统一面板尺寸、折叠状态和拖拽能力，不在页面内硬编码左右/底部面板尺寸。

### 3.2 设置页模板

- [ ] 设置页具备统一的左侧导航、分区标题、保存/重置/校验操作区和变更反馈。
- [ ] 设置项分组稳定，避免把高频开关、低频配置和危险操作混在同一区域。
- [ ] 保存按钮、重置按钮、校验提示和权限提示位置统一。
- [ ] 设置页如未使用工作台模板，已登记为设置类模板而非豁免漏洞。

### 3.3 结构稳定性

- [ ] 页面根、工具栏、搜索区、主表、右侧详情、底部明细、列设置、关键按钮具备稳定 `data-testid`。
- [ ] 页面结构不会因无数据、加载中、错误、权限不足而大幅跳动。
- [ ] 模板插槽命名和使用方式符合现有工作台约定。
- [ ] 不直接依赖旧模板 token 或已禁止导入的旧设置布局。

## 4. 工具栏

### 4.1 工具栏入口

- [ ] 主操作区使用 `WorkbenchToolbar` 或项目认可的统一工具栏封装。
- [ ] 查询、重置、刷新、导入、导出、同步、批量操作、列设置等入口不散落在页面多个 Card 或表格内部。
- [ ] 工具栏在同类页面中的位置、高度、间距和按钮层级保持一致。
- [ ] 低频操作进入“更多”或统一扩展区，不挤占主操作位。

### 4.2 按钮顺序

- [ ] 按钮按统一分组排序：主操作、查询操作、数据操作、批量操作、视图操作、更多操作。
- [ ] 主操作如“新增”“保存”“提交”“审核”位置固定。
- [ ] 查询操作如“查询”“重置”“刷新”位置固定。
- [ ] 数据操作如“导入”“导出”“同步”位置固定。
- [ ] 批量操作必须和选中态联动，并展示选中数量或明确禁用原因。
- [ ] 危险操作如“删除”“取消”“作废”使用统一危险样式和确认流程。

### 4.3 按钮文案与状态

- [ ] 同一动作使用同一中文文案，不混用“查询/搜索/检索”“重置/清空/恢复”“导出/下载”。
- [ ] 按钮禁用时能说明原因，避免用户不知道下一步该做什么。
- [ ] 异步按钮有加载态，避免重复提交。
- [ ] 图标按钮必须有中文 `aria-label` 或可见文本。

## 5. 搜索与筛选

### 5.1 搜索入口

- [ ] 主搜索框位置与同类页面一致，优先位于统一搜索/工具栏区域。
- [ ] 搜索占位符清晰说明可搜索字段，不写泛泛的“请输入”。
- [ ] `Enter` 可触发查询，且行为与点击“查询”一致。
- [ ] 查询后焦点不丢失，用户可继续键盘操作。

### 5.2 高级筛选

- [ ] 高级筛选入口位置统一，展开/收起行为一致。
- [ ] 常用筛选优先展示，低频筛选收纳，避免首屏过度拥挤。
- [ ] 筛选项标签、默认值、空值含义和时间范围控件保持一致。
- [ ] 筛选条件变化后，分页重置规则明确且与同类页面一致。

### 5.3 重置与刷新

- [ ] “重置”表示清空用户筛选并恢复默认查询态。
- [ ] “刷新”表示保留当前筛选、分页或视图上下文重新加载数据。
- [ ] 重置后有清晰反馈，不残留隐藏筛选条件。
- [ ] 刷新失败时提供重试入口和错误说明。

---

## 6. 表格与主数据区

### 6.1 主表契约

- [ ] 主表使用统一表格封装或统一 AG Grid/表格适配层。
- [ ] 工作台列表页优先使用工业紧凑表格预设，例如 `gridPreset="industrial-review-compact"`。
- [ ] 行选择使用统一契约，例如 `selectionCellMode="custom"` 与 `selectionHeaderMode="allInvert"`。
- [ ] 序号列、选择列、固定列、不可隐藏列、不可移动列策略符合统一列策略。
- [ ] 主表不直接裸用 `<Table>` 拼出与模板不一致的主列表；确需使用时必须说明原因。

### 6.2 列与格式

- [ ] 列名使用统一中文术语，和菜单、详情、筛选项保持一致。
- [ ] 金额、数量、重量、体积、时间、状态、布尔值、空值展示格式统一。
- [ ] 状态标签颜色和语义一致，避免同一状态在不同页面用不同颜色。
- [ ] 长文本、编号、备注、地址等列有统一截断、悬浮提示或展开策略。
- [ ] 默认列宽、最小宽度、固定列数量不影响常用操作可见性。

### 6.3 列设置与视图状态

- [ ] 列设置入口固定，文案统一为“列设置”。
- [ ] 列设置支持显示/隐藏、排序、恢复默认和持久化策略。
- [ ] 页面使用统一视图状态控制或统一缓存键，不自定义分散存储规则。
- [ ] 列设置弹层可键盘操作，关闭后焦点返回触发入口。

### 6.4 分页与汇总

- [ ] 分页位置、每页条数、总数展示和刷新行为一致。
- [ ] 汇总信息位置稳定，避免和分页、底部明细或状态栏冲突。
- [ ] 批量选择跨页规则明确，避免用户误以为已选择所有数据。

## 7. 详情、面板与弹层

- [ ] 同类页面详情入口一致，优先使用右侧详情、底部明细或统一详情页模板。
- [ ] 左侧筛选、右侧详情、底部明细的显示/隐藏通过统一面板状态或模板配置控制。
- [ ] 面板折叠按钮、拖拽分割条、最小/最大尺寸和本地记忆策略一致。
- [ ] 弹窗、抽屉、浮层打开后焦点进入有效控件，关闭后焦点返回触发入口。
- [ ] `Esc` 可关闭非阻断弹层；危险确认弹窗不应被误关闭导致状态不明确。
- [ ] 详情、编辑、审核、导入等弹层的标题、按钮顺序和错误提示一致。

---

## 8. 状态展示

### 8.1 数据状态

- [ ] 加载中使用统一骨架屏、Spin 或模板加载态，不改变页面整体结构。
- [ ] 空数据说明当前筛选下无数据，并提供重置、刷新或新建建议。
- [ ] 查询失败说明发生了什么、可能原因和用户可执行的下一步。
- [ ] 权限不足说明缺少的权限或建议联系管理员，不展示技术错误。
- [ ] 部分成功/部分失败展示成功数、失败数和失败明细入口。
- [ ] 后台任务处理中展示任务状态、刷新方式和完成后的反馈位置。

### 8.2 操作反馈

- [ ] 保存、提交、审核、导入、导出、同步等异步操作有成功、失败和处理中反馈。
- [ ] 批量操作反馈包含影响条数和失败明细。
- [ ] 危险操作必须二次确认，确认文案准确说明后果。
- [ ] Toast、Message、Notification、Modal 的使用场景与同类页面一致。

## 9. 文案与术语

### 9.1 中文与编码

- [ ] 所有用户可见文案使用中文，业务确需英文缩写时有明确语境。
- [ ] 页面不显示 `\uXXXX` 形式的 Unicode 转义。
- [ ] 新增或修改文本文件使用 UTF-8，优先 UTF-8 无 BOM。
- [ ] 不出现问号乱码、替换字符乱码或中英文编码混杂。
- [ ] 错误提示、空态、确认文案面向用户，不暴露堆栈、接口路径或技术实现细节。

### 9.2 统一术语

- [ ] 查询动作统一使用“查询”，不在同类按钮中混用“搜索”“检索”。
- [ ] 清空筛选统一使用“重置”，不混用“清空”“恢复”“初始化”。
- [ ] 重新拉取数据统一使用“刷新”，不混用“重新加载”“更新”。
- [ ] 输出数据统一使用“导出”，不混用“下载”“输出”。
- [ ] 表格字段配置统一使用“列设置”，不混用“字段设置”“表头设置”“列配置”。
- [ ] 危险业务动作如“删除”“取消”“作废”“关闭”严格区分含义，不为追求统一而改变业务语义。

### 9.3 标题与说明

- [ ] 页面标题和菜单名称一致，副标题说明页面用途而不是重复标题。
- [ ] 表单字段、筛选字段、表格列、详情字段命名一致。
- [ ] 空态和错误态提供下一步建议，例如“请调整筛选条件后重新查询”。
- [ ] 确认弹窗文案包含对象、动作和后果。

## 10. 可访问性与键盘效率

### 10.1 语义与标签

- [ ] 页面主区域、工具栏、搜索区、主表、详情区具备合理语义或可访问名称。
- [ ] 图标按钮、列设置、折叠按钮、关闭按钮、危险按钮有中文 `aria-label`。
- [ ] 表单控件有可关联的标签，不依赖占位符充当字段名。
- [ ] 状态变化通过可见反馈或可访问公告告知用户。

### 10.2 键盘操作

- [ ] `Tab` 顺序符合视觉顺序：导航、标题、工具栏、搜索、主表、详情或底部区。
- [ ] `Shift + Tab` 可反向返回，不进入隐藏或不可见控件。
- [ ] `Enter` 在搜索区触发查询，在确认弹窗中触发主确认动作。
- [ ] `Esc` 关闭弹层后焦点返回触发入口。
- [ ] 表格行、右键菜单、列设置、页签、命令面板具备基础键盘可用性。

### 10.3 视觉可读性

- [ ] 颜色不作为唯一状态表达，状态标签同时有文字。
- [ ] 主按钮、危险按钮、禁用按钮对比度足够。
- [ ] 紧凑密度下文字不重叠、不截断关键业务信息。
- [ ] 字体缩放、浏览器缩放和窄屏情况下不破坏核心操作入口。

## 11. 测试与门禁

### 11.1 静态与单测

- [ ] 新页面或改造页面补充模板契约测试、文案约束测试或对应组件单测。
- [ ] 涉及 Unicode/中文文案时，确认 `visibleTextEncoding.test.ts` 或同类约束覆盖。
- [ ] 涉及工作台模板时，确认模板采用率脚本仍通过。
- [ ] 涉及表格列设置、选择、视图状态时，补充对应 hook 或组件测试。
- [ ] 涉及 `*.test.tsx` 时，确认 Vitest 配置会运行这些测试。

### 11.2 E2E

- [ ] P0 页面至少覆盖一条关键路径 E2E：进入页面、查询、选择、查看详情或执行主操作。
- [ ] 涉及布局统一时，补工作台布局、面板折叠、列设置或工具栏相关 E2E。
- [ ] 涉及 a11y 时，补或更新 `workbench-a11y` 相关测试。
- [ ] E2E 优先使用 `data-testid`、`getByRole` 和稳定中文文案，不依赖易变 DOM 结构。
- [ ] E2E 不依赖真实不稳定数据；必要时使用项目既有 mock 或 fixture。

### 11.3 建议验证命令

- [ ] 已运行模板采用率检查：`pnpm --dir apps/erp-web run lint:page-templates`。
- [ ] 已运行类型检查：`pnpm --filter erp-web typecheck`。
- [ ] 已运行 lint：`pnpm --filter erp-web lint`。
- [ ] 已运行相关单测：`pnpm --dir apps/erp-web exec vitest --run <相关测试文件>`。
- [ ] 涉及页面渲染或交互时，已运行相关 E2E 或说明未运行原因。
- [ ] 发布前改动已运行构建：`pnpm --filter erp-web build`。

---


### 11.4 基线评分脚本

新增或改造 ERP 页面后，建议先运行统一性评分脚本，确认没有明显降低模板、表格和页面结构趋势。

```bash
pnpm --dir apps/erp-web run assess:ui-uniformity
```

需要在自动化任务中读取结构化结果时，使用 JSON 输出：

```bash
pnpm --dir apps/erp-web run assess:ui-uniformity -- --json
```

如果后续命令要直接解析 JSON，Windows PowerShell 下建议使用脚本原生命令：

```bash
node apps/erp-web/scripts/assess-ui-uniformity.mjs --json
```

检查重点：

- 新增页面是否进入适用页面统计或合理豁免。
- 推荐模板采用率是否保持 `>= 95%`。
- 裸 `Table`、裸 `Card`、半统一旧主表数量是否出现不合理增长。
- P0 页面是否优先接入 `WorkbenchPageTemplate` 和工业表格契约。
- baseline exceptions 是否没有无说明增加。

### 11.5 文档与编码验收

只修改本文档、总体计划或术语表时，执行以下检查：

```bash
python -c "from pathlib import Path; files=[Path('docs/ERP_FRONTEND_UI_UNIFORMITY_PLAN.md'),Path('docs/ERP_FRONTEND_UI_PAGE_CHECKLIST.md'),Path('docs/ERP_FRONTEND_UI_TERMINOLOGY.md')]; [p.read_text(encoding='utf-8') for p in files]; print('utf8 ok')"
pnpm --dir F:\erp run check:utf8
```

如果同时修改页面、模板、脚本或测试，再执行完整前端门禁：

```bash
pnpm --dir apps/erp-web run lint:page-templates
pnpm --filter erp-web typecheck
pnpm --filter erp-web lint
pnpm --filter erp-web build
```

## 12. 豁免登记

### 12.1 允许豁免的情况

- [ ] 登录页、异常页、无权限页等不属于工作台业务流程的页面。
- [ ] 创建/编辑页、详情阅读页、指标看板页已有专用模板且符合统一文案、状态和 a11y 要求。
- [ ] 第三方嵌入页或过渡迁移页无法立即接入模板，但有明确替换计划。
- [ ] 技术诊断页、临时运营页等低频页面，已限制入口和影响范围。

### 12.2 豁免必须包含的信息

- [ ] 页面路径和路由路径。
- [ ] 页面类型和优先级。
- [ ] 豁免的具体规则。
- [ ] 豁免原因，不接受“历史原因”这类模糊描述。
- [ ] 业务负责人或模块归属。
- [ ] 计划清理时间或重新评估时间。
- [ ] 替代约束，例如文案、编码、a11y、测试仍必须通过。

### 12.3 豁免治理

- [ ] 新增豁免不能导致模板采用率低于目标阈值。
- [ ] baseline exceptions 只能减少或明确登记，不能无声增加。
- [ ] 临时豁免必须有到期时间。
- [ ] 豁免页面仍不得出现用户可见 Unicode 转义、乱码、明显视觉断层或危险操作无确认。

## 14. 最低合并标准

- [ ] 新增工作台页面必须使用统一模板或登记有效豁免。
- [ ] P0 页面不得缺失统一工具栏、统一搜索、统一主表和基础 E2E。
- [ ] 页面不得新增用户可见乱码、Unicode 转义或英文残留操作文案。
- [ ] 危险操作不得缺少确认和明确后果说明。
- [ ] 关键图标按钮不得缺少中文可访问名称。
- [ ] 本次改动相关的 lint、typecheck、单测或 E2E 已运行并记录结果。
- [ ] 无法运行的验证命令已说明原因和替代检查方式。
