# 工业级电商 ERP 95%+ Round 14 硬化推进计划

## 本轮目标

- 将 Round 13 已落地的三条主链路（食品批次、数码序列号、鞋服映射规则）从“可用”提升到“可阻断、可审计、可回归”。
- 将子任务执行体系统一到可执行任务卡（front matter + retry/fallback）并降低上游 502 对推进节奏的影响。
- 在本轮结束时给出可复核的工业级差距快照，明确距离 95% 目标的剩余缺口。

- 已确认：
  - `production_date` 已进入 Rust repo/API 真实字段链路。
  - 序列号绑定与发货状态流转主链路可回归。
  - `SHOP_PRODUCT` 映射规则已有版本启停治理能力。
- 新增硬化：
  - 子任务执行器已支持瞬时故障自动重试与本地降级。
  - 已识别并规避 Windows `LNK1140/LNK1318` 的命令粒度风险。

## Round 14 五个子任务

1. R14-01：鞋服映射规则硬校验与错误分级（create/update）
2. R14-02：食品批次效期阻断规则后端化（含禁售窗口）

5. R14-05：Round 14 fresh 验证、日志与工业级差距评估

## 实施策略

- 先跑后端校验硬化，再收口前端字段兼容，最后做 fresh 验证与差距评估。
- 所有子任务卡统一采用：
  - `retry_policy: transient-auto-retry(max=3,delay=10s)`
  - `fallback_strategy: switch-to-local-execution`
- 对 Windows 重型链接目标优先采用小粒度测试命令，避免单条命令阻塞整轮。

## 验证口径

- 后端：`cargo check --lib` + 小粒度单测
- 前端：治理相关 Vitest 定向集
- 任务系统：`pnpm run test:ops` 与 `ops:task:run` 实跑证据

## 交付标准

- 关键规则在后端可阻断并给出可读错误。
- 任务卡体系可执行、可重试、可审计。
