# 商品行业化主档设计

## 背景

当前商品中心已经具备一部分工业级 ERP 商品主数据底座能力：

- 顶层字段已支持 `batch_enabled`、`shelf_life_days`、`forbid_sale_days`、`serial_enabled`、`serial_push_platform`
- 规格行已支持 `color`、`size`、`ingredient`
- 可扩展属性已支持 `attrs`
- SKU 批次、序列号路由与 schema 已存在

当前缺口不在于重建后端底层，而在于把现有能力沉淀成具有行业语义的商品主档配置，重点补齐三类行业场景：

1. 食品保质期与生产日期管理
2. 鞋服尺码与颜色管理
3. 数码产品序列号管理

## 目标

在不大改后端 schema 的前提下，为商品资料页补齐行业模板化管理能力，让商品主档可明确表达：

- 商品属于哪一种行业管理模板
- 食品是否启用生产日期与临期预警策略
- 鞋服是否采用颜色/尺码规格矩阵
- 数码商品是否启用严格序列号规则

并且这些信息需要具备以下特征：

- 可在商品新建/编辑弹窗中配置
- 可回填到表单
- 可稳定写入商品 `attrs`
- 可在商品详情面板中展示
- 可通过 E2E 验证关键联动

## 设计原则

### 1. 不重造底层

本轮不新增后端顶层字段，不重做 SKU 模型，不重做批次和序列号服务，而是复用现有：

- 顶层字段承接通用库存治理能力
- `attrs` 承接行业模板语义
- `specs` 承接鞋服规格矩阵语义

### 2. 顶层字段与行业字段分层

顶层字段保留全局库存控制语义：

- `batch_enabled`
- `shelf_life_days`
- `forbid_sale_days`
- `serial_enabled`
- `serial_push_platform`

行业模板字段统一进入 `attrs`，避免为单个行业持续膨胀顶层 schema。

### 3. 行业语义优先于字段堆砌

不是简单新增几个输入框，而是让商品资料页表达“管理策略”：

- 食品表达的是生产日期与效期策略
- 鞋服表达的是规格矩阵策略
- 数码表达的是序列号追踪策略

## 数据模型设计

### 顶层字段

继续复用现有字段：

| 字段 | 作用 |
| --- | --- |
| `batch_enabled` | 是否启用批次管理 |
| `shelf_life_days` | 保质期天数 |
| `forbid_sale_days` | 禁售提前天数 |
| `serial_enabled` | 是否启用序列号管理 |
| `serial_push_platform` | 是否向平台回传序列号 |

### attrs 字段

新增行业化字段，统一挂在 `attrs`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `industry_profile` | `GENERAL \| FOOD \| APPAREL \| DIGITAL` | 商品行业模板 |
| `production_date_enabled` | `boolean` | 食品是否启用生产日期管理 |
| `shelf_life_unit` | `DAY \| MONTH \| YEAR` | 食品保质期单位 |
| `near_expiry_warning_days` | `number` | 临期预警天数 |
| `variant_mode` | `STANDARD \| APPAREL_MATRIX` | 规格矩阵模式 |
| `apparel_size_system` | `CN \| EU \| US \| INTL` | 鞋服尺码体系 |
| `serial_tracking_mode` | `NONE \| ITEM \| DEVICE` | 数码序列号追踪模式 |
| `serial_outbound_required` | `boolean` | 出库是否必须绑定序列号 |
| `serial_inbound_unique_required` | `boolean` | 入库序列号是否必须唯一 |

### specs 字段

继续复用现有规格行字段：

- `color`
- `size`
- `ingredient`
- `spec_name`

当行业模板为鞋服时，`color` 与 `size` 需要被提升为主规格语义字段，并允许自动拼接 `spec_name` 预览。

## 页面交互设计

### 商品基础信息页

新增“行业模板”选择项：

- 通用商品
- 食品
- 鞋服
- 数码

根据模板切换显示对应行业配置区块。

### 食品区块

食品模板下显示“食品效期管理”卡片或分组，字段包括：

- 启用批次管理
- 启用生产日期管理
- 保质期时长
- 保质期单位
- 临期预警天数
- 禁售提前天数

设计约束：

- 食品默认建议开启批次管理
- 关闭批次管理时，保质期、禁售、临期字段仍可保留但输入框禁用
- 本轮“生产日期”表达为商品级策略，不是单个固定日期值

### 鞋服区块

鞋服模板下显示“鞋服规格矩阵”配置区块：

- 规格模式固定为“颜色 + 尺码”
- 支持配置尺码体系
- 规格区表头和提示语突出颜色、尺码语义
- 当规格名称为空时，基于颜色/尺码显示自动命名预览，如“黑色 / 42码”

本轮不额外引入多维 SKU 引擎，只在现有规格编辑器上增强语义。

### 数码区块

数码模板下显示“设备序列号管理”配置区块：

- 启用唯一码管理
- 序列号追踪模式
- 出库必须绑定序列号
- 入库序列号唯一校验
- 平台回传序列号

设计约束：

- 数码模板默认建议开启 `serial_enabled`
- 未启用唯一码管理时，序列号规则区块禁用但值保留

## 保存与回填设计

### 表单回填

商品详情进入编辑时：

1. 从 `record.attrs` 中读取行业字段
2. 将 `specs` 与其余 `attrs` 分离
3. 行业字段通过 `form.setFieldsValue` 回填
4. 其余未知 `attrs` 继续通过 `attrsSnapshotRef` 保留

### 表单保存

保存时：

1. 从表单读取行业字段
2. 生成 `specs`
3. 将行业字段与 `attrsSnapshotRef.current` 合并
4. 写回 `payload.attrs`
5. 顶层字段保持原有提交流程

这样既能新增行业能力，也不会覆盖已有未知扩展字段。

## 详情展示设计

商品详情面板新增行业主档摘要：

- 行业模板
- 食品效期策略摘要
- 鞋服规格矩阵摘要
- 数码序列号策略摘要

摘要展示以“业务可读”为主，而不是原样展示 JSON。

## 测试设计

本轮采用 TDD，先补商品页 Playwright 用例，再补 UI 实现。

最小验证范围：

1. 打开新建商品弹窗可看到“行业模板”
2. 选择“食品”后出现生产日期/保质期相关字段
3. 选择“鞋服”后出现尺码体系与颜色/尺码矩阵提示
4. 选择“数码”后出现序列号规则字段

增强验证范围：

1. 新建食品商品并保存后，详情显示食品主档摘要
2. 新建鞋服商品并录入颜色/尺码规格后，详情与规格区正常展示
3. 新建数码商品并开启序列号规则后，详情显示序列号策略摘要

## 本轮边界

本轮不做以下内容：

- 批次库存明细中的生产日期流转校验
- WMS 入库单上的生产日期强校验
- 数码设备序列号全链路出入库拦截
- 鞋服批量规格组合器

这些能力应在后续轮次基于本轮商品主档语义继续下钻。
