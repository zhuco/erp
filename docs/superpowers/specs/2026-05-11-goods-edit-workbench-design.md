# 货品编辑工作台升级设计

## 背景

当前货品模块已经具备以下能力：

- 一级菜单“货品”已接入顶部导航。
- 货品与组合装的新建页已经升级为独立工作台页面。
- 货品查询页与组合装查询页已经接入真实接口并可实际使用。

当前仍存在一个明显短板：

- “修改货品”和“修改组合装”仍通过查询页中的 `?edit=` 参数打开 `Drawer` 表单。
- 编辑体验与新建页不一致，工作区被弹层约束，不适合继续扩展更多字段。
- 查询页组件承担了过多编辑职责，后续维护和测试边界不清晰。

本次目标是在不改变现有真实接口协议的前提下，将“修改”能力提升为与“新建”同等级的工业级全工作台编辑体验，并保留查询上下文返回能力。

## 设计目标

### 业务目标

- 将“修改货品”和“修改组合装”升级为独立工作台编辑页。
- 保持货品、组合装编辑链路继续直连现有真实接口，可实际使用。
- 从查询页进入编辑后，返回时保留原查询上下文，包括搜索词、筛选、分页和当前选中记录。

### 体验目标

- 编辑页不再使用全屏 `Drawer`。
- 编辑页与新建页使用统一工作台骨架，但默认更加紧凑。
- 编辑页默认收起右侧摘要面板和底部辅助面板，将更多空间让给主表单。
- 为后续增加更多字段保留结构空间，不把字段重新塞回弹层或碎片化面板。

### 工程目标

- 路由、标题、菜单归属、工作台白名单和测试全部同步升级。
- 对旧的 `?edit=` 入口保留兼容，不引入瞬时断链。
- 尽量复用现有货品表单、组合装表单和工作台壳层，避免重复实现。

## 已确认决策

以下决策已由用户确认：

1. 使用独立编辑路由方案，而不是继续强化 `Drawer`。
2. 编辑完成返回查询页时，必须保留原查询上下文。
3. 编辑页默认收起右侧摘要面板和底部辅助面板，整体布局尽可能紧凑。

## 方案对比

### 方案 A：保留 `Drawer`，仅替换为工作台样式内容

优点：

- 改动最小。
- 回归范围较小。

缺点：

- 本质仍是弹层，无法提供完整工作台纵深。
- 对更多字段扩展不友好。
- 不符合“工业级全工作台编辑体验”的目标。

### 方案 B：在查询页内部切换为编辑工作台模式

优点：

- 查询上下文天然保留。
- 不需要跨路由回传。

缺点：

- 查询页会同时承担列表、详情、筛选和编辑职责，状态复杂。
- URL 语义不清晰，不利于分享、回放和测试。
- 后续维护成本高。

### 方案 C：新增独立编辑路由工作台页

优点：

- 与新建页体验一致，结构最清晰。
- 路由语义明确，易于测试和回放。
- 最适合后续继续扩展字段、摘要区和校验区。

缺点：

- 需要同步改动路由、标题、菜单归属和兼容跳转。

结论：

- 采用方案 C。

## 路由设计

### 新增编辑路由

- 货品编辑页：`/goods/products/:productId/edit`
- 组合装编辑页：`/goods/kits/:kitSkuId/edit`

### 查询页编辑入口改造

以下入口全部从“打开 `Drawer`”改为“跳转独立编辑页”：

- 货品查询页工具栏“修改货品”
- 货品查询页双击行
- 组合装查询页工具栏“修改组合装”
- 组合装查询页双击行

### 旧入口兼容

保留现有兼容入口，但不再实际渲染编辑弹层：

- `/goods/products/query?edit={productId}`
- `/goods/kits/query?edit={kitSkuId}`

兼容策略：

- 查询页检测到 `edit` 参数后，立即重定向到新的独立编辑路由。
- 除 `edit` 外的其余查询参数全部透传，保证历史书签和已有内部跳转不失效。

## 查询上下文保留策略

### 原则

查询上下文不能只依赖 React 内存状态，必须显式进入 URL，确保以下场景都可恢复：

- 从查询页进入编辑页后返回。
- 保存成功后显式跳回查询页。
- 页面刷新后继续保留当前筛选语义。
- 复制查询页链接给他人后可复现当前查询状态。

### 需要保留的上下文字段

首批保留以下字段：

- `keyword`
- `leftFilterKey`
- `brand`
- `category`
- `status`
- `page`
- `pageSize`
- `activeId`

### 上下文传递方式

- 查询页将筛选、分页和当前选中记录同步到 URL。
- 进入编辑页时，将当前查询参数完整拼接到编辑页 URL。
- 编辑页自身不解析这些业务筛选参数，只将其视为“返回查询上下文”。
- 点击“返回查询”或保存成功时，编辑页按原始查询参数回跳到查询页。
- 保存成功时，额外确保 `activeId` 指向刚保存的记录，便于回到列表后继续定位。

## 页面结构设计

### 共享壳层

当前新建页使用 `GoodsCreateWorkbench` 作为工作台壳层。为了避免新建页与编辑页逐步分叉，本次将其提升为更通用的表单工作台壳层，建议命名方向如下：

- `GoodsFormWorkbench`

该共享壳层支持：

- `mode: 'create' | 'edit'`
- 自定义标题、副标题、状态标签
- 自定义返回动作和保存动作
- 自定义右侧摘要面板和底部辅助面板
- 配置默认是否收起右侧面板和底部面板

### 编辑页默认布局

编辑页默认策略：

- 右侧摘要面板默认收起
- 底部辅助面板默认收起
- 主表单区域优先展示

这样既保留工作台的辅助能力，也不牺牲主表单的可编辑空间。

### 表单密度与结构

编辑页继续复用现有 `ProductForm` 和 `KitForm` 的字段与校验，不重做字段域建模。布局上遵循以下规则：

- 基础识别字段优先放在首屏。
- 采购、仓储、库存治理等分区顺序稳定。
- 组合装 BOM 编辑保留在主表单流内，不拆到弹层。
- 分区之间的留白适度压缩，但保持分组标题和阅读节奏清晰。

## 页面职责

### 货品编辑页

职责：

- 拉取货品详情。
- 将详情映射到 `ProductForm`。
- 使用工作台壳层承载编辑体验。
- 保存成功后返回原查询上下文。

顶部动作：

- 返回查询
- 保存修改

右侧摘要信息建议承载：

- 货品编码
- 货品名称
- 品牌与分类
- 当前状态
- 最近更新时间

底部辅助面板建议承载：

- 编辑校验清单
- 接口调用链说明
- 关键主档字段摘要

### 组合装编辑页

职责：

- 拉取 `getKitDetail`
- 拉取 `getSkuDetail`
- 搜索可选组件时继续使用 `searchSkus`
- 将详情映射到 `KitForm`
- 保存后更新 Product、SKU 与 BOM，并返回原查询上下文

顶部动作：

- 返回查询
- 保存修改

右侧摘要信息建议承载：

- KIT SKU
- 组合装名称
- 组件数量
- 最近更新时间

底部辅助面板建议承载：

- BOM 校验清单
- 保存调用链说明
- 关键装配字段摘要

## 数据加载与保存策略

### 货品编辑

数据加载：

- 使用 `getProduct`

保存策略：

- 使用 `updateProduct`

保存成功后：

- 刷新 `products`
- 刷新 `goods-products-query`
- 刷新当前详情缓存
- 返回原查询 URL，并设置 `activeId`

### 组合装编辑

数据加载：

- 使用 `getKitDetail`
- 使用 `getSkuDetail`
- 组件搜索使用 `searchSkus`

保存策略：

- 使用 `updateProduct`
- 使用 `updateSku`
- 使用 `saveKitBom`

保存成功后：

- 刷新 `kits`
- 刷新 `products`
- 刷新 `goods-kits-query`
- 刷新 `goods-products-query`
- 刷新组合装详情相关缓存
- 返回原查询 URL，并设置 `activeId`

## 错误处理与空态

编辑页需要覆盖以下情况：

- 路由参数缺失：提示后回到对应查询页。
- 详情加载失败：在工作台主体显示错误态和重试入口。
- 保存失败：保留当前表单输入，不丢现场，仅提示错误原因。
- 查询上下文缺失：回退到对应查询页默认态，不中断编辑流程。

## 测试策略

### 契约测试

更新 `goods` 模块契约测试，验证：

- 查询页源码不再依赖 `Drawer` 作为实际编辑承载。
- 查询页支持独立 `/edit` 路由跳转。
- 兼容 `?edit=` 旧入口。

### 路由与菜单测试

验证：

- 两个新编辑路由已注册。
- 编辑页路径仍归属于“货品”一级菜单。
- 动态路由标题解析正确。
- 编辑页路径纳入工作台精简白名单。

### 页面行为测试

验证：

- 查询页点击“修改”跳转独立编辑页。
- 双击行跳转独立编辑页。
- 旧 `?edit=` 链接自动跳到新编辑页。
- 编辑页保存后回到原查询上下文。
- 编辑页默认收起右侧和底部辅助面板。

### 回归验证

至少回归以下链路：

- 货品新建
- 货品查询
- 货品编辑
- 组合装新建
- 组合装查询
- 组合装编辑

## 实施顺序

1. 先补测试，锁定新编辑路由、上下文保留和兼容跳转行为。
2. 抽象共享工作台壳层，支持编辑模式与默认收起配置。
3. 新增货品编辑页与组合装编辑页。
4. 改造查询页编辑入口与旧 `?edit=` 兼容跳转。
5. 清理旧 `EditorDialog` 的实际使用路径，必要时保留为过渡壳或删除。
6. 跑测试并进行浏览器回归。

## 验收标准

- “修改货品”和“修改组合装”不再打开 `Drawer`。
- 编辑页为独立工作台路由页面。
- 编辑页与新建页使用统一工作台骨架。
- 编辑页默认收起右侧和底部辅助面板，整体更紧凑。
- 保存后返回原查询上下文，搜索词、筛选、分页和当前记录定位保持正确。
- 旧 `?edit=` 入口仍可用，但实际跳转到新编辑页。
- 关键测试与浏览器回归通过。
