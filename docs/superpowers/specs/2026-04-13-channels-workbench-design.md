# 渠道目录工作台重构设计

**日期**: 2026-04-13

## 目标

将 `/channels` 渠道目录页面重构为基于最新工作区模板的工业级 ERP 工作台页面，同时将“平台授权回调地址”纳入页面的一等信息，用于统一渠道接入说明和后续授权回跳承接。

## 设计结论

本次采用“渠道主数据工作台 + 授权信息中枢”的方案，不把页面做成单纯表格，也不把店铺接入、同步任务、映射配置全部塞进一个大杂烩页面。

页面职责聚焦在三件事：

- 渠道主数据管理
- 平台接入信息总览
- 授权回调地址与接入动作统一展示

## 约束

### 1. 使用最新工作区模板

页面应使用当前仓库最新的工作台模板体系，也就是 `components/workbench/templates/*` 这一层提供的结构语义。允许继续复用 `UiModule03MainTableSection` 这类已接入工作台模板的主表容器，但页面层必须按工作台方式组织左右侧面板和主区信息。

### 2. 授权回调地址由系统自动生成

平台授权回调地址不是渠道字段，不进入 `Channel` 后端模型和数据库表。它应由页面按以下输入动态生成：

- 当前站点 `origin`
- 当前路由基路径
- 路由模式（`browser` / `hash`）
- 当前所选渠道 `channel_id`
- 当前所选平台 `platform`

### 3. 回调地址就是当前页面

授权回调地址必须落回 `/channels` 页面，而不是新增独立页面。页面需要具备识别授权回跳查询参数的能力，并将对应渠道自动聚焦到当前活动行。

### 4. 不扩散为接口改造

本轮不改 `Channel` API，不新增渠道授权持久化字段，不把 `/channels` 改造成直接发起店铺 OAuth 的页面。真正的授权发起仍以店铺接入链路为准，渠道页负责提供标准回调地址、接入说明和导航入口。

## 页面结构

### 主区

保留当前成熟的工业级主表能力：

- 单行活动态
- 多选、Shift/Ctrl 连选
- 右键菜单
- 列查询
- 表尾汇总与分页

主区顶部增加页面级概览信息，突出：

- 渠道总数
- 启用数量
- 当前能力覆盖（手工建单 / 手工售后 / 已配置默认仓）

### 左侧面板

左侧改为页面专属的“运营筛选与工作台说明”面板，替代当前通用 quick filters 占位式体验。

包含：

- 预置业务视图：全部、启用、停用、支持手工建单、支持手工售后、已配置默认仓
- 当前筛选摘要
- 页面级说明：授权回调统一回到当前页

### 右侧面板

右侧详情改为三段式信息结构：

1. 渠道资料
2. 平台授权
3. 联动入口

其中平台授权区需要包含：

- 系统生成的回调地址
- 回调地址只读展示
- 一键复制
- 授权回跳状态提示
- 去店铺接入完成授权

联动入口区提供跳转：

- `/channels/shops`
- `/channels/mappings`
- `/channels/sync-jobs`

## 授权回调方案

### 地址生成

回调地址统一生成到 `/channels`，附带查询参数：

- `auth_callback=1`
- `channel_id=<channel_id>`
- `platform=<platform>`

当路由模式为 `hash` 时，地址格式必须带 hash 路由段；当存在 `routerBasePath` 时，必须带上基路径。

### 页面回跳承接

当 `/channels` 带有授权回跳参数时，页面需要：

- 识别这是一次授权回跳而不是普通访问
- 尝试按 `channel_id` 自动激活对应渠道
- 在头部或右侧授权区给出清晰状态提示
- 不在本轮直接调用缺失的渠道级授权持久化接口

## 交互原则

- 主表负责“活动行”和“批量选择”
- 右侧详情只跟随活动行
- 左侧预置视图负责快速切换业务观察角度
- 列查询负责细粒度过滤
- 授权入口不足时提供明确跳转，不提供假接入动作

至少覆盖以下内容：

- 页面类型检查通过

## 本轮边界

### 包含

- `/channels` 工作台 UI 重构
- 左右侧面板重做
- 回调地址自动生成与展示
- 回跳参数识别与页面提示

### 不包含

- 新增渠道授权数据库字段
- 修改 `Channel` API 契约
- 新增真正的 OAuth callback 持久化流程
- 将店铺接入、同步任务、渠道映射合并为同一页
