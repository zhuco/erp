## 1. 目标与强制边界

最新视觉方向（2026-09-11）：基于网格实验台的风格统一工作台深色/浅色主题。颜色集中于 `workbench/theme.rs`，DataGrid 继续通过 GridTheme 接收；默认深色、右上角切换，切换不重建页面状态。统一表头层次、交替行、输入边界、只读详情文本和字段对齐；刷新成功不显示常驻提示。此方向优先于机械复刻旧浅灰截图的要求，布局与操作约定保持。

工作台最新交互（2026-09-11）：主表工具栏分左操作、中搜索、右设置/帮助/导出三段。搜索覆盖宿主声明的常用字段（如手机号、姓名、快递单号、平台单号），输入框右侧提供清空按钮；设置菜单承载筛选、详情、子表的可见性。序号及其表头居中；结构勾选框必须有可辨边线。`read_only` 限制编辑，不禁止行选择或表头全选/反选。示例分页默认 500，选项为 100/200/300/500/800/1000/2000。

当前无用户、业余自用，旧页面作需求参考，不要求逐页复刻。先让自己的店铺每天用得起来，再服务 3—5 家商家，收入稳定后建设 SaaS。组件投资以减少重复操作、减少误操作、稳定维护为目标。禁止将企业版功能清单直接变成首版全部工期；也不能以分期为理由在迁移中删除现有必需功能。

用户已确认下文“易格 ERP 可用版”作为一个完整交付目标，不拆成两个产品版本；文档修订号和内部实现批次不代表缩小目标。按模块并行实施，使用公共接口接线，不能把已存在的基础交互重复开发。

### 1.0 当前优先级：先打磨网格产品

当前功能范围冻结：仅完成已确认范围、修复具体缺陷和必要验收，不新增对标功能或 ERP 页面。Windows候选窗、系统剪贴板权限、系统DPI、打印机、读屏软件和远端CI属于宿主/交付环境，不作为网格功能完成的前置。组件仍须保证输入事件、编解码、布局和状态契约，不通过持续增建测试工具延长组件开发。

2026-09-10 用户再次明确：当前交付仅为通用网格组件，ERP 业务 UI 尚未开始建设。商品、SKU、订单仅作为组件契约与真实 API 的最小验收宿主；停止扩展录单页面、菜单和业务流程。已有宿主保留，不删除。网格自身的录单编辑器、批量粘贴、校验与保存接口仍在完整范围内；完整 ERP 页面、真实店铺上线与业务流程验收不作为本次组件完成的前置条件。

以高质量 ERP 数据网格为独立基础产品：先在实验台打磨交互和性能，再接真实页面。实验台使用商品、订单、库存结构及可控的大数据/错误夹具，但不把模拟数据当真实业务验收。整体 ERP 菜单和页面不是当前前置。

长期可免费使用 ERP、以业务定制增加收入；当前保持同版核心，不为每个客户复制网格源码。客户列、格式、校验、动作和详情通过明确接口接入；通用缺陷和能力回到主库。暂不建设插件市场、脚本引擎或低代码平台。未来 SaaS 是可选商业阶段，不是唯一收费路径。

产品目标包含企业级列管理、行与单元格选择、编辑、分组汇总、主从、树形数据、导出及透视等。分期代表实现顺序，不是永久放弃高级能力；性能来自双向裁剪、有界缓存、后台计算和避免每帧全量工作，而非职责层数。

### 1.1 全面禁止 AG Grid

1. 社区版、企业版、React 适配及拆分包全部禁止；包括 `ag-grid-community`、`ag-grid-enterprise`、`ag-grid-react`、`@ag-grid-community/*`、`@ag-grid-enterprise/*`，以及 npm alias、CDN、动态加载、转发包和复制源码。
2. 不允许 AG Grid 的运行时、类型、主题、CSS、DOM 协议、模块注册、许可证屏蔽成为新组件依赖。不得在 `DataGrid` 内继续渲染旧引擎。
3. 所有业务数据表格统一接入自研入口 `DataGrid`：主表、子表、底部明细、目录、弹窗选择、编辑明细、数据预览、报表列表、以网格实现的左侧导航。单纯树形导航可以使用树控件；打印文档中的静态表格及说明文档表格不属于交互网格。
4. 禁止新增平行表格实现，包括页面直接使用 Ant Design Table、TanStack Table、其他完整表格引擎或手写业务 `<table>` 绕开统一入口。新 UI 使用 egui 基础控件，不依赖 React/DOM。
5. 自研范围是列模型、查询和选择状态、编辑事务、布局、交互、渲染层及扩展协议。基础工具可以复用，第一阶段允许内部复用 egui 滚动、布局和绘制基础能力；不能向业务层泄漏其对象或把自研解释为完全禁止第三方基础工具。
6. 既有 AG Grid 是冻结的迁移债务。规范生效后不增加依赖点、不扩展旧引擎能力；迁移分批进行，旧文件暂存不等于迁移通过。已迁移页面不得运行时降级回 AG Grid。
7. 官方文档仅作功能体验对标，不要求 API、CSS 或实现兼容，不复制其源码。允许在禁止规则、历史证据及纯 JSON 偏好转换器中保留旧名称。

### 1.2 当前不承诺的内容

- 不建设通用低代码页面引擎、完整电子表格、公式计算引擎、插件市场和任意脚本执行系统。
- Rust 固定 1.98.1，语言与格式风格为 2024；配置更新与编译验收分开。React/Vite 冻结。
- 桌面与 WASM Web 共享一套 Rust/egui 页面。桌面壳不自动带来离线订单/库存写入能力；离线同步另立业务方案。
- 不把文档属性、演示页或文件名检测当成功能实现。每项能力需要运行行为、失败路径和验证证据。

## 4. 功能对标与分级

下表“对标”指公开行为参考，含基础能力和企业增强，不是对 AG Grid 版本收费边界的逐项声明。官网当前文档与仓库 35.2.1 的版本不同，不能推断旧项目已经具备官网全部功能。[官方能力概览](https://www.ag-grid.com/react-data-grid/community-vs-enterprise/)

- **G1**：基础可替代网格，足以承载第一批真实列表。
- **G2**：业务编辑与批量效率，按页面需求补齐后完成迁移。
- **G3**：分析和高级交互，需求明确后再实现。
- 等级是能力层级，不是项目实施时间表。某旧页面依赖 G2/G3 能力时，必须提前实现对应项或明确下线该功能后再迁移；不得静默降级。

| --- | --- | --- | --- |

| DG-19 | 树形数据 | G2 仓库层级、组合商品等真实需求下的展开、懒加载和独立选择规则 | G2 |
| DG-20 | 透视与图表 | G3 分组维度、聚合度量、列数上限和服务端计算；图表消费查询结果 | G3 |
| DG-21 | 行拖动/合并单元格 | G3；有排序/分页时不能把可见位置当持久业务顺序；跨虚拟窗口合并需专项验证 | G3 |
| DG-22 | 本地化、密度、可访问性 | 中文、主题 token、紧凑/标准密度、ARIA、输入法和纯键盘路径 | G1 |

区域选择与剪贴板是独立能力，不能把勾选行当成矩形区域选择。[区域选择参考](https://www.ag-grid.com/react-data-grid/cell-selection/)

分块数据加载与服务端分组/透视需要后端查询配合，前端虚拟化不能代替数据库分页和聚合。[服务端数据模型参考](https://www.ag-grid.com/react-data-grid/server-side-model/)

## 5. Rust 架构与目录

采用 eframe/egui + wgpu，native 窗口与 WASM canvas 共享自绘界面。初始依赖参考 Venue 的 eframe/egui 0.36.1、egui_tiles 0.17.1；接入前核实 Rust 1.98.1 和双端兼容并锁定 Cargo.lock，不自动追随依赖最新版。egui_tiles 按实际多面板需求引入。egui Grid/ScrollArea 并非完整企业数据网格。

目标目录（第一批目录已创建，不代表全部职责已完成）：

```text
crates/erp-grid-core/       # 无 egui/HTTP/OS 的列、查询、选择和编辑状态机
crates/erp-ui-egui/         # 唯一 DataGrid 与其余四类组件，依赖 core
apps/erp-ui/               # 共享业务页面、模型、API 适配和双端入口
  src/platform/native/    # 原生宿主能力
  src/platform/web/       # WASM 宿主能力
  src/lib.rs             # 当前 GridLab 实验台，共享 native/Web
```

组件先作为 workspace 私有 crate，不另建通用 SDK。禁止 Venue 的绝对路径依赖。应用拥有权威数据快照、网络任务与持久化；core 拥有交互状态和草稿；egui 层拥有布局和编辑器焦点。绘制返回意图，应用处理副作用并发布快照。不得让组件反向引用业务页面或直接访问数据库。

native 专用依赖放 target cfg 段，Web 不引入阻塞线程/磁盘 API。后台任务通过有界队列更新模型并 request_repaint；禁止绘制循环中重复发请求。

## 6. 核心契约

### 6.1 Rust 类型与事件契约（历史设计草案；当前公共入口以GRID_INTEGRATION为准）

| 类型 | 必须实现的语义 |
| --- | --- |
| RowId / ColumnId / ScopeKey | 稳定身份 newtype，不能用可见索引充当 ID |
| CellValue | 空、布尔、整数、精确小数、文本、日期和时间枚举；金额不使用浮点事实 |
| ColumnNode | Group/Leaf 枚举；组有稳定 ID 和子列，叶有宽度上下限、显隐、冻结、查询及编辑能力 |
| ColumnSpec | 分离读取值、格式化、查询字段、导出值、编辑解析；绘制回调仅属 egui 层 |
| FilterSpec | 文本/数字/日期/布尔/集合；集合显式区分静态与远端分页选项 |
| FilterExpr / GridQuery | 类型化 And/Or/Predicate 树、排序、分页/游标、schema、时区和空值语义；Local/Remote 枚举隔离 |
| SelectionMode / Selection | None/Single/Multi；显式 ID 或全部匹配凭证加排除 ID；活动行/焦点/勾选独立 |
| GridSnapshot | scope_key、query_key、request_id、revision；Loading/Ready/Error 枚举，Ready 含行与已知/未知总数 |
| GridEvent | 查询、选择、编辑提议、提交与视图变化意图；应用处理 I/O，组件不自行写业务数据 |
| EditPatch | row_id、column_id、original、proposed、expected_version；与 6.4 状态机一致 |
| HostCapabilities | 文件、剪贴板、打印与持久化的能力/不可用原因，禁用不能静默假成功 |

首次 load、后台刷新、缓存失效、保存后重查均由应用发布新 GridSnapshot；load 不是唯一更新渠道。同一查询 revision 单调；旧 request/scope/query 不得覆盖当前快照。旧数据若暂留必须标明过期并禁用写入，跨身份旧数据不可显示。类型接口不得只声明未实现属性，列组、远端筛选选项与选择模式必须在真实组件中验收。

### 6.2 查询、分页和请求竞态

1. 数据模式显式区分 `local`（完整有限集合）与 `remote`（服务器查询）。禁止收到一页数据后在本地排序/过滤，却向用户表达为全量结果。
2. 远端适配器将上述草案转换到现有 OpenAPI；本规范不假设现有后端已支持全部排序、筛选、聚合或选择凭证。缺失能力先补契约及后端测试，界面不得假装成功。
3. 文本查询默认 250 ms 防抖，Enter 立即提交；筛选变化重置页码。提交新请求先取消旧请求，同时比对 `requestId + scopeKey + queryKey`，即使服务端忽略取消，旧结果也不能回写。
4. `queryKey` 由规范化查询、商家/店铺/用户数据范围和查询 schema 计算，并包含分页；全部匹配选择另用 `selectionQueryKey`，不含展示列和分页，禁止混用缓存键。切换商家/账号先执行第 6.7 节离开协议；只有允许切换后才取消旧请求、隔离旧缓存、清空选择并关闭旧草稿，不能在询问用户之前清空输入。
5. 稳定排序追加唯一 ID 作为后端 tie-breaker；数据频繁变化时，offset 分页可能重复/遗漏，G2 按块读取使用快照或游标。不得把“稳定排序”声称为完整快照隔离。
6. 总数未知时显示“已加载 N 条/还有更多”，不得编造总页数；总数缩小时归一化页码后最多重试一次，避免空页循环。
7. G1 沿用页面服务端分页；G2 块缓存由同一适配层管理，默认每块 100 行、最多 10 块，LRU 淘汰，具体上限需基准验证；不能无限加载所有订单。
8. 过滤、排序和汇总都经过后端字段白名单和权限校验；页面传来的商家标识不构成授权。API 必须限制查询复杂度、页大小和导出范围。

### 6.3 选择、焦点和键盘

#### ERP 业务操作范围（优先于下方旧默认描述）

“单选/多选”指数据行，不是字段列。维护三个互不替代的状态：活动行、稳定 RowId 勾选集合、单元格复制区域；键盘焦点另行保存。Shift/Ctrl/Meta 一旦用于数据选择，只能改变行勾选；即使未提供 RowId，也不得退回修改复制区域。Ctrl/Cmd+C 等输入命令除外。

| 输入 | 活动行 | 勾选行 | 复制区域 |
| --- | --- | --- | --- |
| 普通单击数据行 | 激活，不自动勾选 | 保持 | 定位单元格 |
| 点击左侧复选框 | 保持 | 勾选/取消该行 | 保持 |
| Shift 点击复选框 | 保持 | 当前已加载顺序的锚点至终点统一勾选/取消；单次最多 10,000 行，超限保留原状态并提示 | 保持 |
| 无修饰键拖框 | 保持，不跟随拖框终点跳行 | 保持 | 更新复制区域 |
| 数据区 Shift 点击/拖动 | 保持 | 从行锚点连续勾选或取消 | 保持 |
| 数据区 Ctrl/Meta 点击/拖动 | 保持 | 单行切换或拖动连续勾选/取消 | 保持 |
| 普通方向键 | 激活导航到的行 | 保持 | 更新焦点/单元格定位 |
| Space（网格导航焦点） | 保持 | 切换焦点行的勾选 | 保持 |
| Ctrl/Cmd+C（网格焦点） | 保持 | 不参与复制 | 按可见列顺序复制 TSV |

业务操作唯一规则：有勾选只操作勾选行；无勾选则操作活动行；都没有就禁用。点击未勾选行不会把它追加到已有勾选集合。取消最后一个勾选后恢复为当前活动行，操作栏明确显示范围。执行时冻结目标 ID 快照，之后选择变化不改变已发任务；后端仍校验权限、状态和版本。

勾选列固定最左，不参与拖序、字段搜索及区域复制。当前无“全选全部匹配”，不得以视口勾选冒充全量选择。实验台“预览操作对象”仅显示 ID，不发业务请求。

查询范围更换时清除活动行、勾选和坐标选区；同范围翻页通过 rebind_page 保留稳定 ID 勾选，清除位置状态并回到页首，保留横向滚动。同页数据刷新且 ID 顺序未变时通过 adopt_generation 保留焦点、选区和滚动；顺序改变后清坐标选区并按 RowId/ColumnId 恢复仍可见的焦点。列重排只清复制区域和坐标焦点，稳定 ID 的活动/勾选保留。Escape 导航态只清复制区域，不清勾选。当前属于本地数据实现，远端协议仍待接入。

复制限制 10,000 单元格/1 MiB，超限明确失败；多区域以空行分隔，特殊字符按 TSV 引号转义。当前复制显示文本，对公式前缀作文本防护；精确数值导出须单独接 typed export。

#### 表头下可折叠快速搜索行

- 搜索行默认展开；每列按类型提供输入控件，草稿按 ColumnId 保存，拖序后跟随字段；勾选列表头按钮展开/折叠搜索行。
- 搜索按列声明 FilterKind，草稿为类型化 FilterDraft，验证后编译为 Filter：文本包含、金额范围、日期时间范围、枚举集合；不同列之间 AND，枚举同列内 OR。控件仅在草稿实际编辑时通过 GridOutput.quick_search_changed 通知宿主，首次渲染空草稿或滚动不触发查询。宿主输入后自动查询，250 毫秒防抖，输入法组合态不查询；无“应用搜索”按钮，清除立即查询。
- 日期时间字段打开日期/时间弹窗，分别启用起止边界，选择年/月/日、时/分/秒；空端点不限制。当前实验台使用 UTC、秒精度、闭区间；真实业务接入必须声明时区并转换 API 时间戳，不按显示字符串比较。非法日期、闰日和起止倒置阻止应用。
- 金额字段在行内直接展示最小/最大两个输入框，中间 `-`，不使用弹窗；空边界不限、边界包含；实验台采用两位小数，解析为 i64 分，无浮点比较。非法字符、溢出、超精度、下限大于上限均保留草稿并阻止应用。其它币种精度必须另声明，不默认为两位。
- 当前分类的完整候选集合去重后不超过 100 个时，使用下拉复选，提供全选/清除。恰好 100 个包含在内；不得从当前可见页取样冒充完整候选，不得静默截断 101 个值。候选不完整或超过 100 个时当前回退文本搜索；未来远端搜索选择另立协议。
- 分类切换需先调用 bind_category 清除旧草稿和选择，再提供新分类 schema；编译阶段拒绝已不在候选中的值。异步选项还需分类 scope 与请求代次隔离。当前实验台状态/仓库候选来自完整合成分类，不代表真实 API 已有候选端点。
- 未来远端将类型条件转为正式查询 AST；不得仅搜索当前页并声称全量搜索。
- 折叠不清草稿或生效条件，工具栏持续显示生效条件数；重置显式清除条件与结果。
- 输入获得焦点时，方向键、Space、复制和中文组合输入交给输入框；不能触发网格选择、拖列或激活行。
- 查询中显示进度并停用操作预览；结果一次替换并清除旧选择。新输入立即取消旧任务；等待防抖、查询中与草稿无效时禁用操作预览。清除立即替换旧任务。本地实验台分帧限量搜索，不单帧扫描百万行。
- 验收：活动行不勾选；勾选优先及取消末项回退；拖框/复制不改业务目标；勾选不改框选；搜索不触发拖列；折叠保留条件；筛选后 ID 正确且旧选择失效。

#### 统一交互状态机与首期规则

网格同一时刻只有一个主手势：Idle、Selecting（复制）、CheckRows（勾选）、ResizingColumn、MovingColumn、Editing。主手势由按下位置确定，释放结束；不能同一次拖动既选单元格又调整列宽。编辑器/按钮优先处理事件，未消费事件才能进入网格导航。

| 输入 | 明确行为 |
| --- | --- |
| 普通单击/拖动 | 建立或替换矩形区域，活动单元格随终点移动 |
| Shift 点击/方向键 | 使用行锚点连续勾选/取消，不扩展复制区域；查询变更使锚点失效 |
| Ctrl/Meta 从未勾选行拖动 | 连续勾选行，保留区间外勾选，不追加复制矩形 |
| Ctrl/Meta 从已勾选行拖动 | 连续取消勾选；目标状态在按下时固定，不逐帧反转 |
| Escape | 导航态清选；手势态取消当前手势并恢复起始状态；编辑态依编辑协议处理 |
| 拖出视口 | 有上限的自动滚动并扩展选区；远端不得把未加载行假装为已加载 |
| 拖表头/右边缘 | 分别拖序/拖宽；显示落点或宽度反馈，不触发数据选中 |

多选区域采用矩形集合，不为百万单元格分配布尔对象。第一批上限 128 区域，超限明确提示且保留上次合法选择；后续如调整必须给性能证据。每帧拖选从手势开始时的基线计算，避免反复累积或减选抖动。

稳定业务身份与视图坐标分离：业务提交只能用 RowId/ColumnId；复制选区使用视图坐标，行勾选与活动行使用稳定 RowId；实验台不提供真实业务提交。应用改变 scope、查询排序或行顺序时必须递增 view generation；旧坐标选择/锚点/焦点立即失效。列重排首批明确清选；后续增加按稳定身份保留能力必须定义离散选区语义，不得把原位置静默对应到不同字段。

#### 行选择与完整键盘契约

- `activeRowId` 驱动详情；`focusedCell` 决定键盘位置；`selection` 决定批量影响对象，三者互不替代。普通点击默认激活行，复选框只改变勾选；本项目普通点击不得隐式勾选，禁止页面另绑第二套选择处理器。
- Shift 选择当前已加载、当前排序下的连续行；端点缺失或查询已变更时清除锚点，不把未加载行伪装为已选。远端任意跨页范围选择不属于 G1。
- Ctrl/Meta 切换、Space 勾选、方向键导航、Home/End 行内首尾、PageUp/PageDown 视口导航；Ctrl/Meta+A 在网格导航态选择当前页，编辑输入框仍执行原生全选。
- 进入网格使用单一 Tab 入口和稳定 egui ID/焦点协调；编辑态 Tab/Shift+Tab 移动到下一可编辑单元格，Escape 取消本次编辑，Enter 确认草稿。IME composition 期间不能被 Enter/快捷键提前提交。
- 明确区分“当前页全选”“全部匹配”和“反选当前页”；显式 ID 跨页保留时不因新页缺少 ID 将其清空。更换筛选默认清空选择并提示；若产品需要保留，必须单独声明其范围。
- G2 的全部匹配由后端发放绑定权限范围、查询、数量与有效期的凭证；执行前重新校验，采用冻结快照或确认后重新计数的明确策略。过期、范围变化或数量变化需重新确认，不能前端枚举全部行代替。
- 框选、文字选择、行选择不能争抢拖动事件。首期实验台提供 range 模式；后续 text 模式显式切换。列拖宽、编辑器和行内按钮不触发选中。

### 6.4 编辑和批量动作

单元格/行编辑形成草稿变更集：`rowId + field + originalValue + proposedValue + expectedVersion`。提交和完成属于业务适配器，默认不做无回执的乐观“已保存”。

编辑状态：`idle → editing → validating → ready → submitting → committed | partial | conflict | failed | unknown`。用户取消只能取消草稿或停止等待；网络超时后处于 `unknown`，应按操作 ID 查询，不能当失败重复执行。

- 同步/异步校验按字段实现，失效校验响应不得覆盖新输入；只读列、权限和版本在前后端各自校验。
- 原始数据只在响应确认后更新；部分成功只清理已成功草稿，失败项保留错误和输入值。409/版本冲突展示最新值和用户值，禁止自动覆盖。
- G2 批量粘贴先解析为草稿、展示影响和逐格错误，再提交；默认上限 1,000 单元格/1 MiB，超限走导入任务，不能冻结 UI。
- 撤销/重做仅作用于未提交草稿；已提交库存、订单动作不能通过前端 Ctrl+Z 逆转。真正反向业务操作由后端单独定义。
- `BatchActionPanel` 接收显式 ID 或全部匹配凭证和动作定义；请求发出前持久化不含凭据的 clientOperationId 和逐项 itemOperationId，再由服务端关联任务 ID。首次响应丢失也能按 clientOperationId 回查；不能只支持按尚未收到的 jobId 查询。身份与重试规则见下方契约。
- 进度未知就显示处理中；100% 进度不等于全部成功。需要分别展示成功、失败、冲突、未知、已取消，并可导出失败清单。

批量身份协议（G2 实现前必须补齐后端契约）：

1. clientOperationId 标识一次固定的动作/范围/参数，由客户端在发请求前生成；服务端以商家、操作者权限域和该 ID 建立唯一记录，并绑定规范化 payloadHash。创建记录与任务入队必须通过事务/outbox 保证一致；同 ID 同 payload 返回原任务，同 ID 不同 payload 拒绝。
2. 每个业务对象的同一次动作有独立 itemOperationId，服务端在执行副作用前记录并保证幂等。首次 start 响应丢失、进度查询超时、客户端重启时使用原身份回查，不生成新身份猜测重试。
3. getStatus 接收 clientOperationId，返回 notFound、running 或 terminal 及逐项结果。notFound 只表示当前未查到；若可能是最终一致读，仍保持 unknown。仅当服务端可保证 start 的唯一键原子幂等时，允许以原 ID 和完全相同 payload 重发原 start；绝不因此新建操作 ID。
4. 部分失败重试使用独立 retry 请求 ID，并指向原 clientOperationId 和失败 itemOperationId 子集；不可把缩小后的 payload 用原 start ID 重发。明确失败且无副作用/可安全恢复的项才能进入 retry；成功项跳过，unknown 项先回查，业务参数已变化则为新的用户动作并重新确认。
5. pending 操作索引按实例/商家/用户隔离保存，包含身份、动作名和回查所需元数据，不保存令牌或整行个人数据。重新登录同一身份后恢复回查；切换商家不展示旧任务，但不得删除尚未明确终态的索引。服务端应声明幂等记录保留期，过期 unknown 不得自动重发。

批量编辑对标“草稿暂存—提交/取消”，不照搬其行模型限制或 API。[官方批量编辑行为](https://www.ag-grid.com/react-data-grid/cell-editing-batch/)

### 6.5 保存视图与偏好迁移

当前无用户，旧 JSON 转换器仅在明确需要导入旧偏好时建设；新版本自身的持久化状态必须版本化。

- 存储键采用版本化元组编码，例如 `erp.ui.view.v1:<encode([instanceId, merchantId, userId, gridId, viewId])>`；不要简单用点拼接导致 ID 碰撞。数据作用域变化不得误用旧视图。
- 保存列顺序/宽度/显隐/固定、排序、筛选、密度和面板布局；不默认持久化批量选择、编辑草稿、令牌和整行数据。活动行/滚动仅作当前会话恢复，不跨商家恢复。
- 保存 schemaVersion、columnSchemaVersion；加载时迁移字段 ID、丢弃失效列、补新列、收敛最小宽度并再次应用列权限。未知未来版本不覆盖原内容，回到默认并提示。
- 旧 `erp.aggrid.columns` 数据只由独立的纯 JSON 转换器读取。显式映射 `colId/hide/pinned/sortIndex`，保留原记录直到新记录写入并读回成功；转换失败只降级到默认视图，不清除用户旧设置。
- 转换器使用项目自有类型及固定测试夹具，不引入旧库。已有自研列设置窗口可以复用 UI，但必须移除 `GridApi` 等依赖。
- 同一状态更新不能形成“恢复→触发事件→立即覆写旧记录”循环；偏好写入防抖并处理配额、禁用存储、多窗口版本冲突。用户主动重置才删除对应视图。

### 6.6 汇总、复制、导入导出

- 所有汇总标明“当前页 / 已选 / 全部匹配”；远端查询总计必须使用服务端结果，不能用已加载行相加冒充全量。
- G1 复制单元格或已选已加载行；未加载选择不能静默遗漏，应提示加载/导出。G2 区域复制按当前可见列顺序生成 TSV，换行、引号、制表符处理必须可逆。
- CSV 明确 UTF-8、表头、空值和时区；XLSX 将单号/条码设为字符串，金额保留精度。导出公式注入防护覆盖以 `= + - @` 等开头的用户文本，数字字段保持合法数值类型；不将用户输入当公式执行。
- 导出前说明列集合、行范围和数量。全量远端数据由服务端导出任务完成，导出权限再次校验；隐藏权限列不得通过原值或导出旁路暴露。
- G2 XLSX writer 通过独立接口接入，实现前核查维护状态和许可证；不能因项目已安装 `xlsx` 就将旧版本认定为通过评估。
- 导入作为业务流程：文件解析→字段映射→校验预览→提交→结果；预览内部使用同一个 DataGrid。大文件解析可移至 Worker，不能把导入实现混入渲染循环。

### 6.7 离开与草稿保护协议

所有网格编辑器、RecordEditor、路由和商家切换共用一个应用级离开协调器；不能各自弹窗，也不能先更新 scope 再检查草稿。

| 触发 | 处理顺序 | 草稿与待定操作 |
| --- | --- | --- |
| 用户主动切行、关闭、导航、切商家/账号、退出登录 | 先冻结目标意图，提供保存/放弃/继续编辑；继续编辑取消切换，保存须所有草稿提交并确认完成，放弃只丢弃未提交草稿；最后原子切换 | 保存失败/冲突/unknown 保持当前上下文；未提交草稿经确认后才清除 |
| 保存已在进行时再次离开 | 等待明确结果或取消离开；不能再次提交同一逻辑操作 | 网络中断按原身份回查；丢弃草稿不能撤销已发送的操作 |
| 会话过期、权限被撤销、强制退出 | 立即停用数据展示和写入，取消/隔离旧请求；不能要求继续用失效凭据保存 | 旧草稿可仅在当前会话内存隔离暂存，同一身份恢复且权限复核后才提供恢复；切换成其他身份或进程关闭前清除并明确未保存，不跨账号落盘。pending 操作索引按 6.4 节保留 |
| 浏览器硬关闭/崩溃 | beforeunload 仅作尽力提醒，不承诺异步保存成功 | 默认不持久化业务草稿，界面说明此限制；重开后只恢复合法 pending 操作索引并回查 |

业务宿主如明确需要跨重启恢复未提交草稿，可选择启用以下契约；未启用时仍按上表默认不落盘。草稿恢复记录必须同时绑定服务端地址（含代理路径）、tenant、已认证 actor、稳定 grid instance、grid schema/version 和业务 scope，禁止仅凭本地账号名或页面路径恢复；记录不得包含 Bearer token、密码或其他认证凭据。应用启动或重新认证后只展示“可恢复”提示，用户必须显式选择恢复，恢复前再次确认 tenant、actor、权限、grid instance 和 schema，任一不匹配或强制权限失效都必须隐藏并清除当前内存副本，不能继续显示旧草稿。已经明确暂存的记录保持原身份隔离，直到同身份重新认证、用户删除或TTL到期；切换账号不得删除另一个账号的暂存内容。

显式恢复后先读取服务端最新数据和权限，再逐项核对 RowId、版本、字段校验与数据范围；核对失败保留草稿和差异供用户处理，不能自动覆盖或自动提交。恢复流程绝不自动发起业务写入，只有用户再次确认并经过现有提交/回执协议才可发送；未知结果沿用原操作身份回查。宿主必须为草稿记录设置有界容量、单记录大小、总数量和 TTL，超限或过期须明确提示并拒绝继续累积；提供用户可见的单条、当前 scope 和全部清理操作，清理不可影响已发送操作及其回执。

强制退出属于权限边界，不能为保护草稿继续显示旧商家内容。主动离开则必须先获得用户选择，不能套用强制退出路径静默丢稿。处于确认弹窗期间收到强制失效，立即转强制退出流程。

## 7. 双端渲染、性能与可访问性

- 行列双向虚拟化；左右冻结区和中心区共享行高、纵向偏移与命中坐标。首版固定行高，动态行高按需求后置。只绘制可见范围及有界 overscan。
- 编辑器身份绑定 grid/scope/row/column，不绑定虚拟索引；滚动不丢草稿。IME 组合期 Enter 不提交。列拖宽、文本选择、区域选择、滚动各有明确事件归属。
- 缓存和后台任务有上限，绘制不阻塞 I/O，不每帧重排全量数据。高 DPI、多屏缩放、焦点恢复与菜单遮挡实测。
- 提供可见焦点与键盘完整流程，验证 AccessKit/浏览器无障碍树；canvas 截图不等于可访问性通过。

| 验收 | 场景 | 目标（各项实际结果见qa/performance） |
| --- | --- | --- |
| PERF-01 | 本地万行 × 30 列 | 数据就绪到可交互帧 P95 ≤500ms |
| PERF-02 | 万行 × 100 列，左右各冻结 2 列，双向滚动 | 帧间隔 P95 ≤32ms，无持续白洞，记录绘制行列数 |
| PERF-03 | 服务端逻辑百万行，每页 100 行，乱序返回 | 回包到可交互帧 P95 ≤300ms，迟到回写 0 次，不全量下载 |
| PERF-04 | 20 轮页面/查询/视图切换 | 无残留任务，缓存不超限，稳定后内存无持续线性增长 |
| PERF-05 | G2：万行、每秒 100 次更新、持续 60 秒 | 可见更新 P95 ≤200ms，版本回退及丢失 0 次 |

两端独立记录硬件、OS、DPI、浏览器、Rust/依赖版本、release 构建、请求数、原始样本及峰值内存。预热 5 次后至少 30 样本；滚动 3 轮各 10 秒。网络延迟单列并保留端到端数据，不混用不同机器时钟。内存分配器保留容量不直接判泄漏，结合任务/对象/缓存计数验证；未跑标记未验收。

## 8. 其它四类组件的开发契约

### 8.1 QueryPanel / SavedViews

- 字段 schema 定义控件、类型、支持操作符、默认值和选项来源；选择商家/店铺属于查询作用域，普通筛选不得越权改变作用域。
- 普通筛选、表头筛选和高级条件共享第 6 节 AST；有同字段多条件时展示合并结果，禁止互相覆盖后不提示。
- 草稿输入与已提交查询分离，“查询”“重置”“清除某条件”行为明确；保存视图存已提交状态，不存尚未应用的输入。
- 日期快捷项保存为明确的“相对规则”或“固定日期”；恢复“最近 7 天”按当前时间计算，并在 UI 表明语义。
- 选项异步加载支持搜索、分页、取消、空态和失败重试；远端集合筛选的枚举范围与查询权限一致。
- 验收：切店铺后旧请求不回写，刷新恢复列和条件，一次恢复只触发一次查询，删除字段后的旧视图可降级恢复。

### 8.2 EntityPicker

- 泛型对象身份由 `id + scopeKey` 表达，显示标签和对象快照不能代替 ID。公共属性提供 `mode`、`value/onChange`、`searchSource`、`resolveByIds`、`isSelectable`；通过业务适配器映射 SKU、店铺、仓库。
- 单选确认直接返回一个 ID；多选提供已选区、跨页保留和确认/取消。打开时先复制临时选择，取消不得改变外部值。
- 查询使用取消和序号防止旧搜索覆盖新搜索；已选记录不在当前页仍可显示，停用/删除对象显式标记失效，提交时后端复核。
- Enter 确认只在候选导航态生效，输入法组合态不提交；Escape 退出，返回原焦点。扫码枪作为快速输入源时复用搜索/确认协议，不假定所有设备都是键盘输入。
- 候选多列列表和已选明细均使用 DataGrid，不能再建 SKU 专用表格引擎。
- 验收：跨页选中、搜索乱序、停用对象、重复确认、取消还原、中文输入和纯键盘选取。

### 8.3 BatchActionPanel

- 公共输入为 `actionId`、选择范围、后端能力、`start/getStatus/retry/cancel` 适配函数；start 输入 clientOperationId、payloadHash 和逐项 itemOperationId，getStatus 可按 clientOperationId 查询，retry 使用独立请求身份及原失败项引用；全部遵循第 6.4 节。输出任务 ID、逐项结果和业务缓存失效意图，后者经同一适配器更新网格快照。
- 执行前展示动作名称、对象数、当前页/跨页/全部匹配范围、不可执行项及原因。影响库存/履约等动作沿用业务确认和原因要求。
- UI 不把 客户端取消等待当作服务端取消成功；不具备 cancel 能力时仅允许停止等待并保留任务入口。
- 后台任务跨页面可回查；商家切换后不能展示或更新前一商家任务。可重试失败与未知结果按第 6.4 节处理。
- 验收：混合成功/失败/未知、网络中断后回查、重复点击只创建一个逻辑操作、过期全部匹配凭证、部分失败重试无重复副作用。

### 8.4 RecordPanel / RecordEditor

- 公共输入为活动对象 ID、详情数据源、字段 schema、初始版本和提交适配器；日志和附件通过插槽及独立查询接入。
- 快速切行时最新活动 ID 决定展示内容；旧详情回包不能覆盖新行。活动行已删除/无权限时展示清晰状态并停用编辑。
- 有草稿时，切行、关闭、离开页面、切商家/账号及主动退出登录统一经过第 6.7 节协调器，提供保存/放弃/继续编辑；保存失败不得关闭或丢稿。强制退出按独立权限失效路径处理。不可在读取详情时自动写入业务数据。
- 表单的同步/异步校验、提交中禁重入、版本冲突和未知结果与网格编辑共用错误模型；不强制所有表单变成网格编辑器。
- G1 同时支持底部子表与已确认的行内主从展开，均走 DataGrid 并复用同一详情数据源；G2 再扩展自适应高度和远程懒加载。
- 验收：快速切行、草稿保护、并发版本冲突、部分字段错误、取消后原数据不变、详情子表选择不影响主表批量范围。

## 9. Rust 原生桌面与 Rust/WASM Web

两端同时纳入目标，共用 core、egui 组件及业务页面。桌面先验证高风险交互，首条商品闭环在 Web 同样完成；只读 WASM 预览不能冒充完整 Web 产品。浏览器版本是 canvas 自绘界面，不承诺系统控件或任意设备权限。

| 边界 | 原生桌面 | Web |
| --- | --- | --- |
| 网络认证 | 后台 HTTP，系统凭据库保存会话 | fetch、同源 HttpOnly 会话与 CSRF 防护；跨源另定义 CORS/凭据策略，须补后端契约 |
| 文件 | 用户指定路径与系统选择器 | 用户手势上传/下载，无任意磁盘权限 |
| 剪贴板 | 系统接口及失败反馈 | 安全上下文与权限，拒绝时提供手动复制/下载 |
| 持久化 | 应用目录、原子写、版本化恢复 | IndexedDB 等受配额/清除限制的存储，失败不可假成功 |
| 生命周期 | 关闭前协调草稿、有界后台队列 | 标签页恢复后重查；硬关闭仅尽力提醒，不保证异步保存 |
| 打印 | 本地驱动/打印服务 | PDF 下载/用户打印；直连设备须明确桥接授权，不默认静默打印 |

平台能力通过应用宿主接口注入，组件不持有令牌；不得向 WASM bundle 写入平台密钥。两端都经 API 执行业务，不直连数据库。权限失效、草稿保护与 pending 操作回查遵循第 6 节。登录、查询、编辑、保存、失败重试与重连两端分别验收。

## 10. 重写与旧前端退出

当前无用户，先提取商品查询—编辑—保存真实语义，旧页面作为需求证据；未选中的旧功能可明确后置，不要求全量复刻。其余四类组件随真实流程建设。

旧 apps/erp-web 冻结，新页面仅进入 Rust UI；旧源代码/依赖尚存就登记遗留，不声明 AG Grid 清零。新版本不得运行时回退旧引擎。退出旧前端时统一处理 npm 锁/依赖、入口、类型、CSS、注册、许可证屏蔽、测试与发布流程，不删除业务数据或未知用户改动。

源码遗留清零与新产物无旧依赖分开验收。新产物不得携带 AG Grid/React 旧 UI；历史说明和禁止规则可保留名称。旧偏好转换仅按明确需求实现。

## 12. 自动约束设计（当前门禁运行状态以ROADMAP为准）

校验根工具链、CI、workspace 与 rustfmt 一致。固定工具链 fmt --check、Clippy warnings 为错误；具体构建遵守统一入口与固定缓存。core 禁止网络/egui/OS 依赖；公共组件禁止业务反向依赖；native/web 依赖图分开检查。

AG Grid 禁止规则覆盖直接/间接包、alias、CDN、类型/CSS 和其他完整网格绕过，配依赖图、产物检查、评审及失败反例。只 grep 名称不足以证明通过。旧前端只减不增基线与新产物零依赖分开；现有 React 门禁不能代表 Rust UI CI，不能删旧门禁冒充迁移完成。

## 13. 交付与 Rust 工程规范

固定 Rust 1.98.1、Edition 2024、resolver 3、rustfmt edition/style_edition 2024；根配置与 AGENTS 为准。参考官方 Style Guide，不启用 nightly 格式选项。子 crate 继承 edition/rust-version，编辑器与 CI 一致。

交付 core、egui 组件、同组件演示、真实页面及 native/web 宿主，分别记录已实现、已测试、未跑和未部署。Edition 升级需检查语义变化（如环境变量修改新增 unsafe、临时值生命周期），不得机械添加 unsafe 掩盖问题；全量格式迁移单独实施。

低成本模型任务按文件边界、契约和验收拆小；不得以空实现、删功能或仅编译通过交付。实施顺序只维护在路线图。

## 列配置与分页：当前实现契约（2026-09-09）

- 表头右键菜单提供 Columns、Hide column、Lock to left / Unlock column。Columns 面板支持按列名搜索、显示/隐藏、锁定及上下移动；移动代表视觉列顺序，不是数据升降序。仍支持表头拖序、拖宽。
- ColumnId 保持不变，Column.visible / pinned 属于自研列模型。勾选列、序号列默认始终显示，独立于业务列定义，不可隐藏、拖序或参与复制/字段筛选；锁定列排在这两个结构列之后、普通列之前；拖序只在同一锁定组内进行，跨组使用锁定开关。至少保留一列业务字段。
- 锁定区的表头、搜索行、数据单元格采用同一坐标与裁剪规则，横向滚动只移动普通列；键盘定位、鼠标命中和复制使用可见列顺序。显隐/重排清除旧坐标选区和焦点，保留按 RowId 的活动与勾选状态。
- 隐藏列保留列定义和查询条件；显示回来恢复原草稿。Reset search 能清除所有字段条件。隐藏列不参与绘制、键盘访问和复制；列配置能恢复隐藏列。
- 锁定宽度须给普通列保留至少约 64 像素的可用区。锁定过多、拖宽或缩窄窗口超出预算时，从最右锁定列开始解除锁定，并显示可悬停查看的状态提示，避免字段永久被遮挡。
- 列配置、筛选、排序、搜索行显隐和每页行数已接入版本化偏好持久化；当前为本地实验账号、按主表/货品/日志 scope 隔离，不代表已接真实账号服务。桌面与 WASM 共用上述实现，系统窗口及浏览器人工验收另行进行。
- 网格占满宿主分配的高度，滚动条使用独立空间、不覆盖数据；即便仅 10 行或没有结果，横向滚动条也位于网格底部，而非最后一行下方。勾选列与序号列位于水平滚动容器外，轨道起点、内容宽度和滑块比例均排除这两列；结构列不只是覆盖在滚动内容上的遮罩。分页器在网格下方，不随数据滚动；无横向溢出时不强制显示无用滚动条。
- 序号为当前完整筛选/排序结果的连续序号，使用页偏移 + 页内索引 + 1，第二页 100 行从 101 开始；不是稳定业务 ID，也不因勾选变化而改变。
- 独立 Pagination 状态与 show_pagination 控件支持首页/上一页/下一页/末页、页码输入及 10/20/50/100/200/500 行每页；默认 100 行。先过滤完整本地集合，再分页，尾页及空结果严格限界。
- 页码或每页行数改变时递增视图代次，保留勾选 ID，清除旧活动行与复制选区并回到页首；同查询刷新保留合法页码，不无故回第一页。仅排序不清勾选；筛选/父记录/数据范围改变清空并反馈。本地完整结果刷新会移除已不匹配的勾选 ID；远端不能拿当前页做此判断。等待防抖、查询中、无效条件期间禁止翻页及预览旧操作目标。当前已提供本地跨页勾选，尚无服务端分页及全部匹配凭证。

- 子表未完成编辑或粘贴预览时禁止直接收起；父表分页、数据集切换和关闭沿用草稿保护。用户可完成编辑或取消草稿后收起。真实后端保存、权限、远程取消/重试、自适应详情高度和两端人工交互验收仍是后续事项。

## 易格 ERP 可用版：目标范围与完成标准（0.12）

用户已明确先完成 ERP 足够使用的数据网格，再铺开业务 UI。本节是新的目标范围；前文“当前实现契约”及审计表继续记录真实现状，不能把新目标写成已经实现。此前将树形、透视、图表、填充与公式笼统标记为“按需/后期”的安排，以本节和路线图的新阶段为准。对外名称为易格，内部入口与稳定身份保持不变。

### 服务端按需加载的具体含义

当前代码已有 `erp_grid_core::remote` 请求/响应/缓存状态机、应用层 `remote_products` 商品适配器、双端 HTTP 传输及 Products API 网格宿主。0.17 新增真实 PostgreSQL 查询及准确总数分页；隔离数据库的 10,000 条夹具已验证 SQL 语义。全 ERP 数据库迁移、真实账户与浏览器运行尚未验收，远端入口仍只读，不能据此宣布完整服务端闭环完成。

- 例：授权筛选结果共 10,000 条，每页 100 行。首次请求当前页的 100 条及总数元数据，下一页只请求下一页；默认不在客户端下载完整 10,000 条。分页是按需加载的一种交互，滚动分块是另一种；第一条远端闭环以服务端分页为默认，并实现有界块缓存的共同查询契约。
- 本地模式仍适合数量可控的订单货品编辑；本地全量过滤/排序再切片必须标成 Local。当前实验台属于此类。Remote 必须由适配器发出分页/筛选/排序请求，网格不内置商品 SQL 或 API 路径；后端缺少能力时补后端，不能退回全量下载而不告知。
- 请求至少绑定数据源、schema、授权范围、规范化过滤、稳定排序、页范围/游标及请求代次；响应含记录稳定 ID、必要版本、总数或明确的未知总数状态及查询身份。未知总数不伪造页数，跳页失效、失败和取消均有明确状态。底栏区分本地处理耗时和远端请求耗时。
- 筛选和排序应用于全部匹配数据之后再取页；不能只筛当前 100 条。排序包含稳定唯一键，数据并发变化下需要快照/游标或明确一致性边界，不能仅凭排序稳定就宣称不会重复/遗漏。聚合和透视同样不能用当前页冒充全部结果。
- 缓存按查询身份隔离，初始预算沿用每块 100 行、最多 10 块，预取也算预算，需压测校准。更换查询或账号取消旧请求并拒绝迟到响应；请求中、失败时不能用旧页面的结果静默执行新条件下的动作。
- 官方功能参考：[服务端分页](https://www.ag-grid.com/javascript-data-grid/server-side-model-pagination/)。此处仅借鉴交互与职责划分，继续禁止引用 AG Grid 引擎。

### 远端契约实现边界（0.15，商品适配器以后文 0.17 为准）

- RowId 升为 128 位，容纳已有商品接口的完整 UUID；跨 JSON 边界使用规范 UUID 字符串，禁止截断为 64 位、做有碰撞风险的哈希或通过 JavaScript Number 中转。实验台编号仍可构造较小 RowId，不能将实验台父子编号算法用于真实业务身份。
- RemoteQuery 拥有数据源、schema 版本、授权范围身份、按 ColumnId 规范排序的过滤项、全局 search 及排序规则。授权身份是非秘密 scope 标识，不能填入 token。same_selection_scope 排除排序，包含 search，用于判定显式勾选是否可保留；页缓存仍完整绑定查询。
- PageAddress 分别表达 Offset 和 Cursor，RowCount 分别表达 Exact 和 Unknown；不能用已加载行数当总数。RemotePages 同时最多 2 个请求，最多缓存 10 块/1,000 行/8 MiB；默认每页 100，协议上限 500，具体适配器可以更低。LRU 命中复用，重试生成新 ticket；请求取消和清空返回需中止的传输 ticket，迟到回调仍必须被拒绝。
- 成功响应需验证请求身份、记录 ID 不重复、记录数不超请求、精确总数与页长度相符、游标前进、值/列/响应大小有界。snapshot 有值时要求同查询快照身份和总数一致；None 表示实时分页，不承诺并发变更下无遗漏。错误不发布为新页，错误信息有界。
- 现有商品接口是 `/v1/tenants/{tenant_id}/products`：游标分页，最多 200 条，按 created_at/product_id 降序，brand/category/status 精确单值过滤，keyword 跨名称/编码/别名/条码。响应没有总数和快照，所以适配为 Unknown/None。updated_at 仅作为观察到的版本，不代表现有更新接口具备比较并交换保存。
- 商品适配器拒绝任意列排序、Offset 跳页、单列名称包含、多值集合等现有后端不支持的请求；不能静默改语义或在当前页补筛选。商家不匹配的响应整页拒绝；JSON 先限制 8 MiB，UUID 保持完整。后续扩展真实 API 以满足完整 ERP 快速搜索、页码导航、保存冲突和全部匹配目标。
- 已验证一万条总数只申请 100 条、缓存淘汰、重复请求复用、取消/重试/迟到响应、未知总数、重复行 ID、游标不前进、快照/总数冲突、UUID 高位区分、商品查询不偷换语义及商家不匹配拒绝。实际 HTTP 的部分路径已由下节补充；真实数据库、浏览器和网络性能仍待验证。

### 双端传输和远端宿主（0.16 历史基线，分页/筛选以后文 0.17 为准）

- 实验台增加 Lab / Products API 两个入口；有本地未完成草稿时禁止切宿主。Products API 直接复用 DataGrid，服务器地址、商家 UUID、邮箱、密码由用户输入，点击登录才连接 `/auth/login`；成功后以返回的 Bearer 会话请求商品列表。密码提交后清空，token 仅在内存，退出/到期/401/403 清理请求、缓存和选择，不落列偏好或日志。
- 这是现有 Bearer API 的实验接入；桌面凭据库、Web HttpOnly/CSRF 会话适配仍按宿主目标继续实施，不能把内存 token 方案称为这些目标已经完成。
- 原生使用共享 reqwest Client 和一个固定两线程 Tokio runtime；Web 使用 fetch、AbortController 和可读流。HttpTask 的取消/丢弃终止请求，完成后主动重绘；15 秒超时，读取过程中限制 8 MiB，禁止重定向转发登录内容或授权头。诊断只返回 HTTP 状态/连接错误，不展示响应体、密码或 token。
- 商品宿主 Search 是明确的全局 keyword 搜索，250 ms 防抖，输入法组合期间等待；新输入立即撤销旧任务和旧页。搜索条件进入查询身份，条件切换清勾选；刷新、翻页和页大小变化保留勾选 ID。当前已加载页不参与全量本地筛选。
- 游标分页提供首页、上一页、下一页及 20/50/100/200 行每页，默认 100；显示 Total unknown，不伪造末页或任意跳页。最多保留 64 个回退游标，超出后可回首页重新开始；完整页码导航依赖后端扩展，仍在目标内。底栏显示勾选数、当页返回行数和网络请求耗时。
- 现有商品 API 缺少任意排序、逐列包含/多值过滤和条件保存；这个宿主保持只读，GridState.sorting_enabled/filtering_enabled 明确禁用对应控件。列宽/显隐/勾选/复制仍由 DataGrid 处理。完整快速搜索、编辑/保存/复制商品、底部真实子表及“全部匹配”均不能据此标为完成。
- 76 项原生回归包含真实本地 TCP 请求的参数编码、Authorization、取消、401、重定向拒绝、过大响应拒绝；egui 输入帧实际点击下一页，验证游标请求、显示商品、跨页勾选及搜索清理，拒绝登录不创建会话。测试服务不等于 ERP API/数据库，Web 当前仅静态检查，真实浏览器 CORS、IME、下载及双端业务保存仍需独立验收。

### 商品服务端查询与准确分页（0.17）

- 新增 `POST /v1/tenants/{tenant_id}/products/query`，OpenAPI 源文件与合并产物同步维护。请求使用核心库 `PageQuery`，只含 schema、offset、limit、filters、sorts、search；授权由服务端 JWT 和路径商家校验决定，不能由客户端 scope 授权。接口要求 `skus.read`，按项目既有规范映射权限。只读维护模式允许此精确 POST 查询路由，不放开商品写操作。
- 商品 schema 1 对应 0 编码、1 名称、2 品牌、3 分类、4 状态、5 创建时间 UTC、6 更新时间 UTC。文本列支持字面包含及多值精确匹配；日期支持 UTC 起止秒范围。多列条件为 AND；全局 search 在名称/编码/别名/条码间为 OR。不能把全局搜索当成单列筛选。时间使用 YYYYMMDDHHMMSS 民用时间键，不能误当 Unix 时间；结束秒包含该秒内的小数时间戳。商品这七列没有金额字段，不代表其他 ERP 明细的远端金额查询已完成。
- 服务端列名和排序字段走固定白名单；值、枚举数组、商家、页大小和 offset 都绑定为 SQL 参数。包含搜索将 `%`、`_`、`!` 视为字面字符；空值/NULL 在文本匹配中统一为空串。多列排序按用户优先级，文本忽略大小写、空值末尾，最终用 product_id 降序打破并列；未排序时 created_at/product_id 降序。数据库排序规则可能因部署 locale 不同而影响文字顺序，不宣称与客户端 Unicode 排序完全一致。
- 查询先限定商家并排除 DELETED，再筛选、排序、分页。count 和 page 在同一个 REPEATABLE READ READ ONLY 事务中执行，每条 SQL 超时 10 秒；返回准确 total 及最多 500 条必要字段。页间仍是实时数据，不发行跨页快照凭证；并发插入/删除下不能承诺跨页永无重复/遗漏，批量动作也不能只信客户端勾选数。
- Products API 宿主已切换此接口：启用逐列快速搜索与多列排序，默认每页 100，支持 10/20/50/100/200/500、首页/末页/前后页及页码输入。远端序号使用 u64，避免 WASM 32 位 usize 截断。隐藏搜索保留条件；重置清除条件；非法日期保留草稿且重试不能恢复旧条件结果。新条件清勾选，排序和翻页保留稳定 ID，输入防抖期间的排序也必须按真实查询范围决定是否清除。
- 品牌/分类/状态的完整枚举目录尚未接入，因此当前这些远端列使用文本输入；接口已经支持多值过滤，但不得从当前页凑下拉选项。命名视图、AND/OR 编辑器、全部匹配凭证、保存冲突、复制商品和真实底部子表仍继续实施。
- 已通过后端 check 和 5 项针对性测试：权限/商家/非法参数及真实路由 2 项、SQL 白名单/UTC 2 项、PostgreSQL 10,000 行查询 1 项。数据库测试只在 [隔离测试集群](../qa/README.md) 使用连接临时表，结束后停止该集群；不修改已有业务数据库。它不等于真实账号登录、整个 ERP 数据库迁移及双端业务保存验收。UI 与质量检查结果记录在路线图，不因接口存在而预先标为全部通过。

### 三种勾选范围，必须分别验收

| 操作 | 目标集合 | 验收例子 |
| --- | --- | --- |
| 勾选当前页 | 当前已加载页内具备选择资格的 RowId | 第 1 页 100 条全选，不自动选剩余 9,900 条 |
| 跨页勾选 | 同一筛选与授权范围的显式 RowId 集合 | 第 1 页勾 3 条，第 2 页勾 2 条，显示勾选 5 条；返回第 1 页仍显示那 3 条，批量动作提交 5 个 ID |
| 全部匹配 | 后端绑定权限/筛选/快照/数量/有效期的凭证及排除 ID | 显式选择全部 10,000 条，再取消 2 条，影响范围为 9,998；不把它转换为客户端无界下载 |

- 活动行、显式勾选和复制框选保持原有独立契约；有勾选时操作勾选集合，没有勾选时操作当前活动行。跨页累计勾选不把多页单元格拼成一个复制矩形。
- 页码、页大小和仅排序变化不清显式勾选；排序变化清除位置相关的 Shift 锚点和复制矩形。选择范围键绑定数据源、schema、授权和过滤，不包含页码、展示列及仅排序；页缓存键仍包含排序与页范围。
- 更换筛选默认清空勾选并反馈；账号/商家或数据源切换先完成既有草稿离开协议，再清空。不能把后台删除、停用、失去权限的 ID 当作成功处理，动作提交时由后端复核并返回逐项结果。
- 显式勾选初始上限 10,000 个 ID，达到上限明确拒绝继续累计并提供“全部匹配”路径（仅后端已支持时）；不能只保留最后一页。首版 Shift 区间操作只作用于当前已加载连续行，任意未加载跨页区间另定义服务端范围契约。
- 参考：[服务端行选择](https://www.ag-grid.com/javascript-data-grid/server-side-model-selection/)。凭证与失效处理是易格 ERP 的业务契约，并非宣称 AG Grid 自动提供 ERP 权限或批量任务后端。

### 业务动作与复制商品

- 网格提供稳定动作 ID、按当前活动行/勾选集合冻结的目标、单项/批量限制、可用状态与禁用原因，宿主负责权限和业务适配。动作未知时拒绝执行，不推断为其他动作。
- “复制商品”生成新业务对象，与复制单元格 TSV 分开。商品适配器决定复制字段、子项、图片引用和默认值，清除原业务身份、库存/销量等不可继承状态，按规则生成新身份，执行校验、保存和结果定位。
- 网格不得按可见文本拼装新商品；隐藏字段、价格权限和版本由业务接口校验。重试沿用同一逻辑操作身份，未知结果先回查，批量复制反馈逐项结果。0.18 已增加后端商品动作接口与核心状态机，实验台远端按钮、进度面板及保存接线尚未完成。

### 业务动作实现边界（0.18）

- 核心库 `actions` 提供 `ActionSpec`、`ActionCommand`、`ActionBatch` 和 `ActionReceipt`。表格右键动作由稳定 ID、标签、目标数量范围及禁用原因描述；禁用原因以悬停提示呈现。宿主未注册的动作必须报错，不能推断为其他操作。当前活动行/跨页勾选集合在调用时冻结，单元格复制选区不参与目标计算。
- 每个目标使用独立非空操作 UUID。批次最多 10,000 项，命令按字段/字符串开销估计限制 8 MiB，冻结过程中即检查预算。并发发送前先确认当前项状态；Sending/Unknown 存在时不自动继续。Unknown 经原操作回执查询后才能同身份重发；取消只影响未发送项。结果列表只保留有界的成功身份/版本或拒绝摘要，不把返回单元格值重复存成另一份大表缓存。
- 新增 `POST /v1/tenants/{tenant_id}/products/actions`，支持 `products.copy` 和 `products.update`；`GET /v1/tenants/{tenant_id}/products/actions/{operation_id}` 回查当前登录用户的结果。业务拒绝也返回持久化的 Rejected 回执，HTTP 200 不等于业务成功。400 为非法请求，409 为同身份异载荷，503 视为结果待核实。回查 404 不能证明此前请求不会提交，只允许原命令、原身份重发。
- 使用迁移 `0096_grid_product_operations.sql`，按 tenant + actor + operation 唯一。命令、商品/SKU/BOM 变更、成功操作日志、审计与回执在同一个 REPEATABLE READ 事务提交；不沿用旧接口先写商品、再写关系、最后补日志的分离流程。重试直接返回已提交回执；同身份不同规范化 JSON 命令拒绝。回执无自动 TTL，清理必须保留防重复所需身份。每条语句超时 10 秒、锁等待 3 秒。
- 动作接口同时要求商品读取与写入权限，商家和 actor 由认证上下文决定；回查按当前 actor 隔离，管理员也不自动读取其他 actor 的操作。维护只读模式禁止动作；新动作路径的只读配置读取失败时拒绝执行。真实部署仍需整体认证/数据范围/数据库迁移验收，不能用这些局部检查替代全系统验收。
- `products.update` 当前支持编码、名称、品牌、分类四列，必须携带观察到的 updated_at。服务端锁定目标并比较版本，更新版本至少递增 1 微秒；旧版本返回 VERSION_CONFLICT。名称不可空，其他空字符串转 NULL，值限制 4096 字节。状态转换、价格、整批粘贴及跨对象保存不能借此接口绕过业务校验。编码冲突返回 DUPLICATE_CODE，回滚变更但保留拒绝回执。

### 动作恢复与宿主执行器（0.19，更新上节实现边界）

- 核心 `ActionBatch::checkpoint/restore` 保留原命令、操作 UUID 与有界结果摘要。恢复时 Sending、Unknown、RetryReady 统一进入 Unknown，先回查；恢复不会自行发送请求。初始 Ready 仍表示从未获准发送。反序列化最多接受 10,000 项，随后校验命令、重复身份、版本及串行批次的未决数量；宿主整个恢复记录另限 16 MiB。
- 新增 RetryReady：回查 404 后可沿用原身份重发，但前次请求仍可能在服务端提交，不能被“取消未发送项”误标为取消。IdentityConflict 表示服务端已将该身份绑定另一命令，重启后仍暂停，不允许自动回查并接受另一命令的结果，也不自动换新 UUID。
- `apps/erp-ui/src/remote_actions.rs` 的 ActionRunner 已实现商品动作 HTTP 执行协议：每次 POST 前产生 CheckpointWrite，只有宿主原子持久化成功并确认对应 CheckpointTicket 后才允许发出；保存失败保持原记录且不发送。票据隔离执行器实例与修订，旧回调不能放行新任务。存储端必须串行提交，不得用内存赋值、eframe 的稍后自动保存或未完成的异步写入冒充持久化成功。
- ActionScope 精确绑定规范化 API 根地址（含代理路径）、商家和用户；用户身份必须来自认证后的服务端信息。不同范围不能恢复或驱动同一执行器。记录不包含密码、Bearer token 等认证凭据；业务草稿与身份仍属于需要保护的本地数据。恢复文件解析失败或存储容量不足必须显式阻止新动作，不能覆盖未决记录后继续。
- 业务回执必须同时匹配 operation_id、source、command_fingerprint。后者覆盖动作类型、操作/源身份、观察版本和所有提交字段，不能只比较商品 ID。HTTP 409 或同身份回执的指纹不匹配均保持 IdentityConflict；无回执、响应格式错误、401/403、连接中断等不能当作写入未发生。404 回查只允许原命令原身份重发；成功/业务拒绝结果也先等待保存检查点，才继续下一项。
- 指纹算法固定为 `sha256-v1:` 加 64 位小写十六进制 SHA-256：依次输入 UTF-8 前缀 `erp-grid-action-v1` 和一个 NUL 字节、operation_id/source 的 16 字节大端值、动作字符串、版本存在标记（单字节 0/1）及存在时的版本字符串、字段数（u64 大端）、按 ColumnId 升序排列的字段编号（u64 大端）和字符串。每个字符串先写 UTF-8 字节长度（u64 大端）再写内容。算法不依赖 JSON 键顺序或空白；版本前缀不得随意复用。
- 新商品回执均包含 command_fingerprint。0.18 历史回执只有在同一 tenant/actor/operation 账本行中存在不可变原命令时，才可在读取时计算补全；禁止从客户端提交的候选命令补值。账本内回执身份/指纹与原命令矛盾时拒绝读取；不修改旧命令、不重做复制、不新增业务迁移。
- 核心动作工厂额外检查返回命令的 source 必须等于被冻结的选中行，禁止回调把未选商品替换进批次。HTTP 执行器会保留完整返回值供宿主消费，批次历史只存摘要；宿主应按返回新对象身份定位，不把复制结果错误绑定原商品。

本节落地的是核心恢复格式、受存储确认约束的 HTTP 执行器及后端回执契约。当前测试用检查点字节模拟重启，用实际回环 TCP 验证断线/回查/重放，不能据此宣称真实磁盘或浏览器存储已完成。桌面原子持久化、浏览器存储、认证用户身份接入、退出/重启恢复面板、复制按钮、批量进度、版本编辑器和结果定位仍需继续实施；远端界面目前仍只读。大批次检查点序列化/保存的性能也须优化和实测，尚未获得双端交互及性能验收。

### 宿主动作持久化（0.20，更新 0.19 的存储实现状态）

- `apps/erp-ui/src/action_store.rs` 提供异步打开、读取和按存储版本提交检查点的宿主适配。调用者必须等 StorageTask 返回成功，才能确认对应 CheckpointTicket 并允许 HTTP 写入。放弃观察存储任务不等于取消事务；提交结果不明时重新打开存储核对版本与原命令，不能直接确认成功或无条件覆盖。
- 检查点仍按 API 根地址、tenant、actor 分区；存储键是固定 `scope-v1:` 前缀加规范化 ActionScope JSON。每个分区保存一个当前批次，最多 32 个分区，每条记录最多 16 MiB，修订最多 JavaScript 可精确表示的整数上限。超限明确失败并保留既有记录，不自动清理未决数据。
- 每个存储实例同时最多一个提交。不同实例、窗口或进程用存储修订 compare-and-swap：两个写入者看到相同旧修订时，最多一个可提交。提交前校验原、新检查点；未决批次不能被不同命令替换，已发送项不能回退为 Ready 或 Cancelled，终态不能改写；开始新批次不能复用上一批的操作 ID。终态回执的业务真伪仍以服务端为准，客户端存储校验不替代认证或后端审计。
- 桌面复用 SQLx 0.7.4 SQLite 驱动，使用 DELETE journal 和 synchronous EXTRA，确认实际同步模式及 4096 字节页大小。事务先取得写锁，再读取/校验/CAS/提交；任何错误由事务回滚保护旧记录。每个池只有一个连接，锁等待 3 秒、取连接 5 秒；数据库页数限制 262144（1 GiB 主文件，不是整个目录的操作系统硬配额）。实际 I/O 和原/新记录校验在复用的后台 runtime 执行，不在 egui 绘制中访问磁盘。[SQLite 同步级别与事务说明](https://www.sqlite.org/pragma.html#pragma_synchronous)。
- 默认文件为 Windows `%LOCALAPPDATA%/ErpGrid/actions-v1.sqlite3`、macOS `$HOME/Library/Application Support/ErpGrid/actions-v1.sqlite3`、Linux `$XDG_DATA_HOME/erp-grid/actions-v1.sqlite3`（未设置时使用 `$HOME/.local/share`）。检查目录为绝对路径且无 `..`，检查祖先和数据库侧文件的符号链接/Windows 重解析点，Windows UNC 网络共享不接受。数据目录、SQLite 文件及 journal 是恢复数据，不属于构建缓存，不按任务换目录，也不自动删除、VACUUM 或重置损坏数据库。
- 浏览器使用 IndexedDB 数据库 `erp-grid-actions-v1`、`checkpoints` object store。平台适配采用薄 JavaScript 模块调用浏览器事务；UI、动作状态、作用域及命令校验继续由 Rust 实现，没有新增 React/HTML 业务界面。写入事务必须是 `durability: strict`，检查实际 durability；不支持时明确失败，不能降级后报告成功。只在 transaction complete 后确认提交，不把 put request success 当作落盘完成。[IndexedDB 事务选项](https://developer.mozilla.org/en-US/docs/Web/API/IDBDatabase/transaction)。
- 浏览器适配在第一次 await 前复制 WASM 字节视图，避免 Rust 释放/复用内存后改变待保存内容；事务内部再次比较旧修订并在同一事务检查分区数量。记录格式异常、配额耗尽、事务中止、版本冲突及不支持严格持久化均拒绝写入。浏览器用户清除数据、存储回收后的服务端任务找回仍需后续任务历史接口，不能将 IndexedDB 当成服务端唯一业务账本。

已验证真实 SQLite 重开、两个写入者竞争、事务失败不改旧记录、未决批次/其他账号不能覆盖、损坏记录与配额拒绝，以及强制结束本测试创建的子进程时未提交事务回滚。磁盘检查点与 HTTP 执行器联测覆盖“POST 响应丢失 → 从 SQLite 恢复 → GET 原回执 → 保存终态”，只产生一次复制 POST。浏览器使用独立 QA origin 和固定测试 profile，在真实 Edge 152 中验证读写、并发/CAS、字节视图复制、故障注入、strict、容量限制，并在关闭及重新启动浏览器后读回原检查点；这不是整个 Rust/WASM UI 的运行验收，也不等于真实断电测试。

Products API 页面已通过 `/me` 绑定当前商家与账号，复用以上存储和执行器接入“复制商品”：无勾选时操作当前行，有勾选时操作全部已勾选 ID；每项生成独立 UUID，发出前保存，显示成功/失败计数与失败原因，成功后刷新当前查询。“定位副本”用服务端返回的新商品身份和当前业务编码契约查询副本。暂停、取消未发送项、恢复继续、未知结果回查与存储失败重新读取均在同一工具栏处理；恢复未决任务不会自动发起写入。复制和恢复重试要求商品读写权限，后端继续独立鉴权。筛选输入等待或无效时禁止开始复制，动作回执不能抹掉非法条件错误。功能解释仅放悬停提示。

### 远端选项目录与全部匹配选择契约（0.23）

- 商品接口 `POST /v1/tenants/{tenant_id}/products/options` 是受 `skus.read` 与商家边界保护的读请求。品牌、分类、状态按完整查询范围去重；去掉目标列自身条件，保留其他条件和全局搜索。选项搜索按字面子串，NULL 和空串合并为空选项，计数和当页在同一只读事务中读取。最多返回 100 个选项，不用商品当前页推导目录。
- 通用 `OptionDirectory` 管理身份、请求代次、取消、错误和重试；取消后重新请求必须使用新代次。仅无选项搜索、offset=0、total≤100 且返回完整集合时，目录可视为固定多选列表。分页目录和搜索结果不能冒充完整目录。商品宿主串行加载三列目录，输入时取消旧任务；大目录通过 `Filter values` 搜索、分页及多选，勾选后沿用 250 ms 自动查询，不添加“应用搜索”步骤。

### 失败粘贴重试与原记录查证（0.33）

### 复制失败项重新审核（0.34）

- “批量任务”中终态且存在拒绝项的商品复制任务可重新审核。服务端只取原任务 REJECTED 成员，读取当前有效商品及最新版本，建立十分钟冻结审核快照；成功、取消和未知项不参与。源商品删除时明确报出不可用身份，不静默漏掉目标。
- `POST /products/copy-batches/{batch_id}/retry-review` 使用稳定 `request_id`，返回原批次身份、请求身份与可复用的 selection 凭据。租户和账号隔离，要求读写权限；同请求始终返回原快照，包括过期后的重试，不偷偷换版本。新审核需显式关闭后重新发起。

- 原任务和原失败回执保持不变。新任务创建响应丢失时保留原新批次 ID，通过任务列表找回或同身份重试。审核关闭只取消客户端读取；短期快照按原过期规则失效，幂等身份记录保留。
- 此增量覆盖商品复制失败项的全部重审，不新增后台调度器，也不代表所有业务动作、草稿恢复、远端填充/撤销和真实账号双端验收已经完成。

### 未提交草稿暂存与恢复（0.35）

- 快照只有单元格意图、原版本和稳定身份，不包含可执行命令、操作ID或登录凭据。绑定server（含代理路径）、tenant、actor、grid及schema；SKU的parent同时进入网格scope和单元格数据。每份最多10,000格、1MiB，单值最多4,096字节，七天到期；复制与序列化前先检查累计预算。

### 0.57 订单代表宿主的恢复与金额契约

订单金额快捷行直接使用Money双输入；服务端按非负分单位解析上下限，包含边界，完整授权范围筛选后再分页。字段类型也声明为Money，不能只通过显示文本猜金额。非法条件不得派发请求。

订单保存使用prepared→持久化Unknown提交确认→HTTP派发→结果核对/清除。未派发编辑可恢复并由用户明确保存或放弃；Unknown保留原版本和请求体，不自动重发、不因过期清空。正常运行写入的checkpoint不得再次作为重启恢复记录执行。账号身份变化、损坏存储、提交不确定均阻止新派发。

恢复事务复用SQLite/IndexedDB平台适配，不能用eframe偏好缓存的flush/get_string作为关键写前持久化确认。每账号只有一个当前订单槽，使用独立key；共享checkpoint总配额32槽，清除保留revision标记防止旧窗口覆盖。存储只负责提交与CAS，订单scope/字段/原请求一致性由typed codec和宿主状态机校验；库不承载订单业务规则。

GridState::restore_edit是宿主恢复入口：稳定RowId/ColumnId、受限文本、无现有编辑器时才接受；始终要求明确提交。当前Web刷新恢复已有实际闭环证据，原生存储有SQLite重开测试，原生实际输入验收仍单列。

- 仅适用宿主确认成员及位置未变的live缓存行。冻结页、记录增删、影响排序/筛选/隐藏业务谓词的更新必须重新查询；未缓存行、未知字段和版本断链显式返回错误，不静默吞掉。
- 每批1至1000项、文本和结构估算合计最多1MiB；缓存仍受既有1000行/10块/8MiB约束。重叠块的同一行必须全部核对并更新，任一副本不一致则整批不变；只暂存变化行，不重建完整数据集。
- 成功回执列出变化行和取消ticket，所有旧在途请求在核心层失效，宿主中止传输并请求重绘。此操作不提交业务写入，不清除选择和草稿；编辑行的外来版本变化由宿主明确呈现冲突。
- 该契约是PERF-05的基础，尚不能代替有界传输队列、逐帧合并、实际渲染延迟与60秒双端测量。
- 公共`UpdateQueue`提供帧边界投递缓冲，每队列绑定订阅generation，最多1000项/1MiB。保留所有版本转移和字段变化，不用最后一个局部补丁覆盖之前的局部补丁；`flush`成功才清空。超限、非法输入或应用失败锁定错误，宿主停止订阅并重新同步后新建队列，不自动重试。过期生产者被拒绝但不污染当前订阅。此缓冲不是网络通道，网络接收侧也必须有界。
- `GridState::notify_row_changed`标记未提交编辑的外来行版本冲突，保留输入及原值，阻断键盘和宿主提交路径。用户明确审核新版本并由宿主更新CAS基准后才可`rebase_edit`，或取消编辑。awaiting操作不受该通知改写，继续按原操作回执解析，不能把外来更新当作保存成功。
- `RemotePages::stats`提供只读缓存块/行/页面负载估算字节/在途请求/错误数，供PERF-04采样。估算不等于分配器或进程/GPU内存；clear后核心状态归零，也不等于传输任务已经退出，宿主必须另核对取消ticket对应任务。
