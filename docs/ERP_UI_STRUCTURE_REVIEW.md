# 旧 ERP UI 与 Rust 外壳结构审查

日期：2026-09-11。范围：只读检查旧源代码归档与当前 Rust UI；本次只记录分析，不修改运行界面，不编译。旧代码存在不代表业务已验收，菜单入口也不代表 API 闭环完成。

## 结论

当前 Rust UI 是最小商品宿主，并未恢复旧工作台结构。最大差别是把全局导航放到了左侧，而旧版通过顶部模块菜单导航，左侧留给页面业务筛选。应先修正应用外壳和页面面板的分工，再迁移业务；继续复用 DataGrid 和真实 API，不重新实现网格。

## 源码依据

旧代码位于 `qa/legacy-web-retirement/source.zip`，本次直接读取，没有恢复旧依赖。

- `src/app/layout/menu.tsx`：模块、分组、路由、权限及功能开关字段。
- `headerMenuModel.ts`、`ModuleHeader.tsx`：顶部模块、分组功能菜单、功能搜索。
- `WorkbenchLayout.tsx`：左右及底部区域、路由对应面板、拖动尺寸、布局记忆、权限过滤。
- `RouteTabs.tsx`、`tabsStore.ts`：标签切换、刷新、关闭当前/其他/全部、快捷键、按租户及用户保存标签状态。
- `src/components/ui-modules/index.ts`：查询、工具栏、主表、子表、详情、策略及设置模块。
- 当前 `apps/erp-ui/src/workspace_shell.rs`、`erp_app.rs`、`remote_view.rs`：五个固定页面枚举、左侧导航及真实商品宿主。

归档中文内容是有效 UTF-8；此前终端显示乱码属于输出编码问题，不能据此认为菜单名称已损坏。

## 旧菜单目录

| 顶层模块 | 旧入口范围 |
| --- | --- |
| 首页 | 工作台 |
| 目录 | 渠道、快递、标签、仓库、物流费、供应商；客户分类/等级/标签；容器、寄方、库区、货位；权限、角色 |
| 销售 | 订单查询、订单审核、订单复核、销售设置 |
| 货品 | 货品新建、货品查询、新建组合装、组合装查询 |
| 履约 | 库存查询、波次执行、出库发货、物流异常、退换补发 |
| 经营 | 利润分析、计划执行 |
| 报表 | 销售统计、接口集成、系统观测 |

先以这些稳定业务名称及分组作参考。接口集成、系统观测的语义更接近管理设置，可在后续业务接入时调整归属；不需要本轮新建系统模块。未接入功能不显示可点击的空页面，不把所有旧菜单恢复当成首期交付要求。

## 布局和模块差距

| 区域 | 旧版职责 | 当前 Rust | 调整建议 |
| --- | --- | --- | --- |
| 顶部 | 模块菜单、分组入口、功能搜索 | 只有品牌标题 | 恢复顶部导航，搜索仅索引可访问且已接入的页面 |
| 标签 | 业务页面切换及批量关闭、刷新、记忆 | 五类单例，基本切换及脏关闭 | 增加溢出滚动、右键操作；刷新/批量关闭沿用草稿保护 |
| 左侧 | 页面筛选、分类树、统计分组 | 全局菜单占用240宽 | 改成可选业务面板；没有内容则不占位 |
| 主区 | 操作工具栏、查询、主表与底栏 | 商品 API + DataGrid，混有实验台工具 | 保留业务动作；诊断、夹具跳转留在实验台 |
| 底部 | 主行联动的货品、日志等明细 | SKU 子表 | 保留，内容标签由各页定义；高度按页面保存 |
| 右侧 | 主行详情、编辑、业务操作 | 商品字段编辑 | 抽出公共面板布局，字段及动作仍由页面实现 |

旧 `UiModule01–08` 已区分查询、工具栏、主表、子表、详情、策略表、设置布局、左侧筛选。Rust 中应按职责命名，不机械复制编号，也不把订单审核模板中的业务规则搬进通用网格。

颜色与密度继续参考已核对的旧主题：主色#1f3a5f，浅色背景，正文12.8，表头24/行21；左240、右360、底280为默认尺寸，允许受可用空间约束。尺寸记忆必须区分页面，不能由一个页面改变其他页面。

## 简单且易维护的落地方式

1. 一份页面注册表负责 PageId、模块、分组、名称、权限及是否已接入；菜单、功能搜索、标签名称从它生成，避免维护三份映射。权限过滤仅控制呈现，服务端仍负责授权。
2. 外壳只管理导航、标签和关闭协调；页面持有查询、选中行、草稿、后台任务和面板尺寸。共享登录/API 客户端可以保留，商品与订单的可变页面状态不继续堆进同一个 RemoteProductView。
3. 一个工作台布局负责可选左/右/底面板、分隔条与主区域；页面提供内容。DataGrid 仍只负责网格交互，不知道菜单和订单路由。
4. 偏好按账号、PageId、实例和网格区分；后台结果携带页面/查询代次，关闭页面取消任务，未应用的结果不能写入另一页。

不增加新的运行服务、插件框架或通用页面脚本引擎。先在现有 crate 内拆模块即可。
