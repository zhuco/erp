# 开发协作与前端规范

## 项目目录与职责映射
- `apps/erp-web/`：前端应用（Vite + React + Ant Design），页面路由、UI 组件与交互逻辑。  
- `crates/`：后端 Rust workspace（API、业务域、仓储、适配器、Worker）。  
- `openapi/`：接口契约与前端客户端生成依据。  
- `migrations/`：数据库结构与演进脚本。  
- `docs/spec/`：架构与数据模型规格（如订单状态机、库存模型、商品模型）。  

## 多AI协作开发约定
1. **契约优先**：`openapi/erp_api_v1.yaml` 作为前后端单一契约源。  
2. **规格对齐**：核心链路需对齐 `docs/spec/04_order_status_machine.md`、`docs/spec/inventory_schema.md`、`docs/spec/product_sku_schema.md`、`docs/spec/kit_bom.md`。  
3. **任务拆分**：  
   - AI-后端：API 与业务逻辑（`crates/erp-api`, `crates/erp-domain`, `crates/erp-repo`）。  
   - AI-前端：页面与交互（`apps/erp-web/src/pages`, `apps/erp-web/src/features`）。  
   - AI-集成：平台适配/消息链路（`crates/adapter-*`, `crates/erp-worker`）。  
4. **冲突规避**：避免多人同时修改同一文件；先更新文档与契约，再进入实现。  

## Workbench UI 统一规范
Workbench UI 与模块化规范已合并至 `docs/web/UI_MODULES.md`，包含布局、页签、面板、工具栏、配色、排版与密度规范。后续以该文档为唯一入口，避免重复维护。  

## 联调与测试建议（多AI并行）
- **订单链路**：接口与状态机一致性、拆合单与多包裹、退款关闭回写。  
- **出入库链路**：预占释放、台账一致性、部分收货/发货。  
- **商品与套装**：生命周期状态可控、KIT BOM 展开与库存扣减一致。  
- **UI 回归**：重点验证项见 `docs/web/UI_MODULES.md`（Workbench 标签页、面板开关、路由标题）。  
## 功能范围锁定
- 以 `docs/spec/erp-feature-catalog` 为唯一功能范围清单。  
- 任何新增功能必须先更新文档并获得确认，再进入实现。  
- 多AI开发时，提交说明需标注“补充说明/实现细化/缺陷修复”，避免隐性扩展范围。  

## AI理解清单
- 阅读顺序建议：`00-范围与命名规范` → `01/03/05` 核心链路 → 其他模块 → 本文件。  
- 任何数据口径/状态流转必须引用 `docs/spec/` 与 `openapi/`。  
- UI 规范统一参考 `docs/web/UI_MODULES.md`。
