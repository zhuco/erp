# 开发协作与前端规范

## 1. 目标

本文件只负责说明前端协作边界、文档入口和长期页面标准，不再重复维护完整 UI 细则。

完整 UI 规范唯一入口：

1. `docs/web/UI_DEVELOPMENT_STANDARD.md`

## 2. 当前统一的前端页面标准

ERP Web 当前只保留两类长期页面标准：

1. 一体化数据作业台
2. 设置型页面

对应代码入口为：

1. 一体化数据作业台：`WorkbenchPageTemplate`
2. 设置型页面：`SettingsPageTemplate`

旧命名只允许作为历史术语出现，不再作为公共规范入口使用：

1. `WorkbenchMainTableTemplate`
2. `WorkbenchToolbarTemplate`
3. `review / recheck / query` 三分叉主表路线

## 3. 协作规则

1. 开始做新页面前，先判断它属于一体化数据作业台还是设置型页面。
2. 涉及主数据工作台页面时，必须优先复用一体化数据作业台，不得新增并行模板路线。
3. 修改高频页面时，优先改共享骨架与统一内核，不优先堆页面补丁。
4. 页面业务动作可以保留在页面层，但必须通过统一工作台动作区接入。
5. 涉及字号、标题层级、工作台区域职责或统一交互规则变更时，必须同步更新 `docs/web/UI_DEVELOPMENT_STANDARD.md`。
6. 如确需偏离共享标准，必须先补设计文档并说明原因和适用范围。

## 4. 实施前检查

开始做页面开发前，先确认：

1. 这是主数据工作台页面还是设置型页面。
2. 是否已经存在可复用的一体化数据作业台入口。
3. 页面差异是否只落在数据范围、过滤 schema、列 schema 和业务动作。
4. 是否需要隐藏右侧详情或底部子表，以及是否通过统一配置实现。
5. 是否需要补单测或 E2E 才能保护共享行为。
6. 是否需要同步更新 UI 规范或设计文档。
