# 商品与主数据

## 模块定位
统一维护商品与主数据，支撑全链路业务一致性（采购、销售、仓储、财务）。

## 业务对象/单据
- SPU/SKU、条码、品牌、品类
- 组合套装、组装品、包装层级
- 供应商、客户、仓库、库位等主数据

## 功能清单与流程
### 1. SPU/SKU建模
**适用角色**：商品管理员、系统管理员  
**流程**：  
1. 维护SPU基础信息（品牌、品类、税率）。  
2. 按规格生成SKU并配置属性（颜色、尺码等）。  
3. 校验必填字段后发布到业务模块。  
**关键规则**：  
- 支持多渠道SKU映射。  
- 支持SKU停用与历史保留。  
**输出**：可用SKU清单。  

### 2. 条码与包装层级
**适用角色**：仓储主管、商品管理员  
**流程**：  
1. 维护商品条码、箱规、包装层级。  
2. 设定箱/件/最小单位的换算关系。  
3. 提交后同步至WMS与标签打印。  
**关键规则**：  
- 支持一品多码与批次条码。  
- 禁止同一码绑定多个SKU。  
**输出**：包装/条码清单。  

### 3. 多单位与计量转换
**适用角色**：仓储主管、采购专员  
**流程**：  
1. 设定主计量单位与辅助单位。  
2. 配置换算比例与取整规则。  
3. 在采购/销售/仓储环节自动换算。  
**关键规则**：  
- 支持按业务场景配置取整方式。  
- 变更需生成生效版本。  
**输出**：单位换算规则。  

### 4. 组合套装与组装品
**适用角色**：商品管理员、仓储主管  
**流程**：  
1. 维护套装/组合结构与组成明细。  
2. 设定拆包、组装或虚拟组合规则。  
3. 出入库时自动拆分或扣减库存。  
**关键规则**：  
- 支持组装品可售库存计算。  
- 组合变更需重新核算成本。  
**输出**：组合规则与库存联动。  

### 5. 商品渠道可售与上架
**适用角色**：店铺运营、商品管理员  
**流程**：  
1. 配置各渠道/区域的可售范围。  
2. 设定上架时间、禁售规则。  
3. 同步至订单接入与渠道系统。  
**关键规则**：  
- 支持按仓库维度控制可售。  
- 渠道禁售需及时释放库存占用。  
**输出**：渠道商品可售清单。  

### 6. 主数据治理与变更控制
**适用角色**：系统管理员、数据管理员  
**流程**：  
1. 统一维护供应商、客户、仓库等主数据。  
2. 变更发起后进入审批流程。  
3. 变更生效后自动同步各业务模块。  
**关键规则**：  
- 支持版本化管理与审计追踪。  
- 提供主数据冲突检测与合并机制。  
**输出**：主数据版本与同步日志。 

### 7. 商品生命周期与删除规则
**生命周期状态**：`DRAFT`（草稿）→ `ACTIVE`（可售）→ `DISABLED`（停用）→ `ARCHIVED`（归档）→ `DELETED`（软删除）。  
**创建与发布流程**：  
1. 创建商品主档与SKU（参考 `docs/spec/product_sku_schema.md`）。  
2. 维护条码、单位、税率、渠道映射与价格。  
3. 审核通过后发布为可售状态。  
**删除/下架流程**：  
1. 校验依赖：库存 `on_hand/reserved`、未完成订单、在途采购/调拨、渠道映射。  
2. 先执行停用（`is_active=false`），禁止新订单进入。  
3. 清理渠道映射与价格，进入归档状态。  
4. 满足约束后执行软删除（保留历史订单引用）。  
**删除校验矩阵**：  
- 有库存或在途库存 → 禁止删除，仅可停用。  
- 存在未完成订单 → 禁止删除，需订单完结后再归档。  
- 渠道映射仍存在 → 需先解绑后再归档。  

### 8. 组合装链路（KIT BOM）细化
**建模**：`skus.sku_kind=KIT`，组件关系存于 `sku_boms`（参考 `docs/spec/kit_bom.md`）。  
**可售库存算法**：可售套装量 = `min(组件可用库存 / 组件数量)`，需扣减 `reserved`。  
**履约链路**：  
1. 订单进入后将套装展开为组件行用于拣货与分配。  
2. 库存预占按组件生成 `inventory_reservations`。  
3. 出库时按组件写入 `inventory_ledgers(SHIP)`，并回写套装发货状态。  
4. 退货可按组件或整套策略入库，需记录选择依据。  
**成本规则**：  
- 套装成本由组件成本合计；若预组装入库则形成新的入库成本。  
- 组件变更需触发套装成本与可售量重算。  
### 9. 商品数据结构对齐（现有模型）
**数据结构**：  
- `products`：SPU 主档信息（名称、品牌、品类、属性）。  
- `skus`：SKU 明细（`sku_code` 唯一、条码、规格、体积重量）。  
- `channel_sku_mappings`：平台/店铺 SKU 映射（唯一键：`tenant_id + shop_id + platform + platform_sku_id`）。  
- `sku_boms`：套装/组合 SKU 组件关系（参见 `docs/spec/kit_bom.md`）。  
**约束要点**：  
- SKU 编码与条码保持租户内唯一，防止重复映射。  
- 套装 SKU 仅作为组合引用，不与普通 SKU 混用库存规则。  

### 10. 商品变更对下游影响清单
- **名称/规格变更**：影响搜索与展示，不应影响库存台账。  
- **条码/包装变更**：同步至 WMS 扫码与打印模板。  
- **单位/换算变更**：影响采购、入库、出库数量换算。  
- **SKU 停用**：禁止新订单与渠道上架，但保留历史订单引用。  
- **BOM 变更**：触发套装可售量与成本重算。  

## 对齐与边界说明
**模块边界**：商品主数据是源数据，不负责订单价格计算与促销规则。  
**输入**：商品录入、渠道 SKU 映射、BOM 维护与条码配置。  
**输出**：SKU 主档、条码/包装层级、套装关系与可售规则。  
**协同模块**：价格与促销在营销模块，库存占用与出库在仓储模块。  
**验收要点**：SKU 唯一性、停用后不可下单、套装库存计算一致。
