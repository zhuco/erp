# 销售与订单管理（OMS）

## 模块定位
统一接入全渠道订单，完成订单标准化、审单、配货、结算与开票的闭环管理，并向仓储与物流发出履约指令。

## 业务对象/单据
- 销售订单、拆分订单、合并订单
- 订单审核记录、异常单处理单
- 发货指令、结算单、销售发票

## 功能清单与流程
### 1. 渠道订单接入与去重
**适用角色**：销售主管、系统管理员  
**流程**：  
1. 配置渠道/平台接口、店铺账号与授权。  
2. 定时拉取或实时推送订单，完成字段映射与数据校验。  
3. 按订单号、支付单号、物流单号多维去重，生成“待审单”记录。  
**关键规则**：  
- 支持多渠道订单号合并为统一内部订单号。  
- 支持缺失字段补全（收货地址、税号、发票类型）。  
**输出**：标准化订单进入审单池。  

### 2. 订单标准化与风险校验
**适用角色**：审单员、销售客服  
**流程**：  
1. 校验客户黑名单、异常地址、历史退货率。  
2. 校验支付状态、发票要求、配送限制（冷链/危险品）。  
3. 风险单进入人工复核，正常单自动流转。  
**关键规则**：  
- 支持风控规则配置与分级处置。  
- 支持可疑订单自动冻结库存。  
**输出**：订单状态更新为“已审/待复核”。  

### 3. 价格与促销结算
**适用角色**：销售主管、财务会计  
**流程**：  
1. 读取渠道价格、会员价、合同价。  
2. 调用营销规则引擎计算折扣、满减、赠品（含随机赠品）。  
3. 生成应收金额与优惠明细，回写订单。  
**关键规则**：  
- 支持多币种与税率规则。  
- 促销叠加规则可配置（互斥/优先级）。  
**输出**：订单金额锁定并进入配货流程。  

### 4. 审单与拆合单
**适用角色**：审单员、销售主管  
**流程**：  
1. 按履约仓库、商品属性、收货地址进行拆分建议。  
2. 审单员确认拆分/合并策略，生成子单。  
3. 关键变更记录审计日志并通知相关岗位。  
**关键规则**：  
- 支持多仓拆分、跨境订单单独拆分。  
- 合并单需保证同一客户与同一地址。  
**输出**：子订单进入库存占用。  

### 5. 库存占用与配货策略
**适用角色**：仓储主管、销售主管  
**流程**：  
1. 根据仓库优先级与可用量进行预占。  
2. 缺货订单进入补货/调拨建议池。  
3. 完成占用后下发出库指令。  
**关键规则**：  
- 支持安全库存阈值与占用优先级。  
- 支持预售/期货订单冻结库存。  
**输出**：出库指令推送至WMS。  

### 6. 发货协同与状态回写
**适用角色**：仓库客服、销售客服  
**流程**：  
1. 订单状态同步为“拣货中/已发货”。  
2. 获取运单号并回写订单。  
3. 物流轨迹更新后同步至客户服务视图。  
**关键规则**：  
- 支持多包裹与分批发货。  
- 允许手工补录运单号与异常备注。  
**输出**：订单全链路状态可追踪。  

### 7. 销售结算与对账
**适用角色**：财务会计、销售主管  
**流程**：  
1. 按渠道生成结算周期与应收对账单。  
2. 校验退款、拒收、改价差异。  
3. 完成对账后生成收款计划与核销记录。  
**关键规则**：  
- 支持代销/平台扣点结算。  
- 支持多渠道对账规则模板。  
**输出**：结算单与核销凭证。  

### 8. 销售发票管理
**适用角色**：财务会计、销售客服  
**流程**：  
1. 收集客户开票信息与发票类型。  
2. 按订单/批量生成发票申请。  
3. 开票结果回写订单并通知客户。  
**关键规则**：  
- 支持电子发票与纸质发票。  
- 支持拆分开票与红冲流程。  
**输出**：发票记录与税务凭证。  

### 9. 订单异常处理
**适用角色**：销售客服、仓库客服  
**流程**：  
1. 识别异常（地址错误、物流异常、超时未发）。  
2. 创建异常处理单并分派责任人。  
3. 处理结果回写订单并触发通知。  
**关键规则**：  
- 支持异常类型模板与SLA。  
- 异常关闭需保留责任归因。  
**输出**：异常处理闭环记录。 

### 9.1 无效货品处理（审核页快速修复）
**适用页面**：订单审核（`/orders/review`）、网店订单转审核（`/orders`）  
**触发条件**：订单行 SKU 未匹配，订单/订单行标记 `MAPPING_MISSING`。  
**权限说明**：  
- `orders.write`：允许执行按规则重匹配、驳回、转审核等操作。  
- `channel_sku_mappings.write`：允许手动匹配货品；无权限仅展示无效标记与原因。  
**交互提示**：  
1. 在列表筛选“无效货品”并勾选订单，可批量操作。  
2. **按规则重匹配**：重新根据映射规则匹配 SKU，成功后清除无效标记。  
3. **手动匹配**：弹窗选择 ERP 货品，可勾选“应用到相同平台编码/规格编码”，保存映射后自动刷新。  
4. **驳回到网店订单**：将订单退回待转审核队列，并提示“在转审核页重新转审以触发自动匹配”。  
5. **转审核**：将订单回到审核队列并重新匹配货品。  
**原因说明**：  
- 平台未提供商家编码（`outer_sku_id` 为空）。  
- ERP 货品档案缺关键编码/条码（平台编码存在但仍无法匹配）。  
**相关接口**：  
- `POST /v1/tenants/{tenant_id}/orders/{order_id}/items/rematch`：按规则重匹配订单行。  
- `POST /v1/tenants/{tenant_id}/orders/{order_id}/return-to-download`：驳回到网店订单。  
- `POST /v1/tenants/{tenant_id}/orders/{order_id}/review/requeue`：转审核。  
- 以上接口在 `/v1/tenants/{tenant_id}/oms/...` 下提供同义路径。  
**建议路径**：  
- 多订单共享同一无效货品时，优先在“渠道货品映射”维护映射，再回到审单页执行重匹配。  

### 10. 订单链路状态机（与现有架构对齐）
**说明**：平台订单为准，订单状态只做映射、不做推测。完整映射参考 `docs/spec/04_order_status_machine.md`，字段映射参考 `docs/spec/03_order_field_mapping.md`。  
**核心状态**：  
- `PENDING_PAYMENT`：订单已创建未支付。  
- `PENDING_SHIPMENT`：已支付待发货。  
- `PARTIALLY_SHIPPED`：部分发货。  
- `SHIPPED`：已发货待签收。  
- `COMPLETED`：交易完成。  
- `CANCELLED`：取消（支付前或平台撤销）。  
- `CLOSED`：关闭（超时关闭/退款后关闭）。  
- `REFUNDING`：退款/售后处理中。  
- `REFUNDED`：退款完成。  
- `ON_HOLD`：风控/暂停履约。  
**链路关键节点**：  
1. 接入订单后完成状态映射，写入 `orders`/`order_items` 快照，并追加 `order_events` 记录。  
2. 审单/风控为内部处理状态（可单独字段维护），不直接改变平台状态。  
3. 库存占用：生成 `inventory_reservations`（唯一 `order_item_id`），并同步可用库存。  
4. 出库/发货：释放预占并写入 `inventory_ledgers(SHIP)`，同步物流状态。  
5. 售后/退款：更新售后单并映射为 `REFUNDING/REFUNDED`，必要时关闭订单。  
**一致性要求**：  
- 任意状态变化需标记来源（webhook/poll/manual）与时间戳。  
- 拆/合单需保留平台订单溯源字段，保证可追踪。  

### 11. 订单链路测试清单
- 新订单→审单→占用→出库→签收→完成。  
- 订单取消→释放库存→不生成结算单。  
- 部分发货→`PARTIALLY_SHIPPED`→补发后`SHIPPED`。  
- 退款中→退款完成→订单关闭。  
- 风控冻结→解除后继续履约。  
- 多包裹/拆单→订单状态与包裹数一致。  
### 12. 链路落地与数据对齐（现有架构）
**入口事件**：`erp-channel` 接收 Webhook → `inbox_events`/`inbox_dedup` → `outbox_events(INBOX_EVENT_RECEIVED)`。  
**消息分发**：`erp-dispatcher` 发布 NATS → `erp-worker` 消费处理。  
**数据落地**：`erp-worker` 解析订单并 upsert `orders`/`order_items`（保存最新快照）。  
**业务动作**：审单、拆合单、库存占用、结算/开票均由 `erp-api` 驱动（契约见 `openapi/erp_api_v1.yaml`）。  
**状态映射**：严格遵循 `docs/spec/04_order_status_machine.md`，内部流程不直接改平台状态。  
**幂等去重**：以平台订单号/支付单号/物流单号做多维去重，保证重复事件不生成新单。  

### 13. 订单链路输入输出清单（便于AI实现）
**输入**：平台订单快照、价格/促销规则、风控规则、渠道与店铺配置。  
**输出**：订单快照、拆合单结果、库存预占记录、出库指令、结算与发票记录、售后触发标记。  

### 14. 模块边界与协同
**OMS职责**：订单接入标准化、审单、拆合单、库存占用、结算与开票。  
**协同模块**：WMS 执行拣货/出库，TMS 管理运单/轨迹，CRM 负责会员与客户画像，财务负责成本核算。  
**边界规则**：OMS 不直接改平台状态，状态变化以平台事件映射为准。
